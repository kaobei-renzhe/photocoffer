# 存照（photocoffer）项目总则

## 这是什么

给摄影师的**本地**图片库桌面应用。核心承诺：照片不搬家（只建索引和缩略图，原图原地不动）、默认完全离线、数据只在本机。

技术栈：Electron 45 + electron-vite + React 18 + TypeScript(strict) + Tailwind v4 + better-sqlite3 + sharp + onnxruntime-node。

## 三进程边界（必须守住）

| 目录 | 职责 | 绝对禁止 |
| --- | --- | --- |
| `src/main/` | 窗口、SQLite、sharp、onnxruntime、文件系统 | 写 UI 逻辑 |
| `src/preload/` | contextBridge 转发 | 写业务逻辑 |
| `src/renderer/` | React 界面 | **import 任何 Node 模块** |
| `src/shared/` | 两边共用的纯类型 | 放实现代码 |

在 renderer 里 `import fs` 是最常见的错误。需要文件能力一律走 IPC。

## 硬性禁止

- 禁止新增运行时依赖，除非能说明：体积增量、能否离线、为什么现有能力不够。
- 禁止绕过任何涉及**用户照片安全**的逻辑（导入、移动、覆盖、删除）。
- 界面文案一律中文，不留英文占位。
- 项目**没有** eslint / prettier，不要自作主张引入。

> 做事流程（方案先行、改动边界、分批落地、验收标准、禁止编造引用）见 `05-协作红线.md`，这里不重复。

## 语言与风格

- 注释、提交信息、界面文案全部中文。
- 注释解释**为什么**，不解释"是什么"（代码本身能说明是什么）。
- 组件内部顺序：类型 → state → 派生值 → effect → 事件处理 → return。

## 交互对象

用户是独立开发者兼摄影爱好者，会自己读代码。回复给结论和证据（文件:行号、实测数字、命令输出），不要客套话和过程铺垫。
