# 主进程与数据层规范

## IPC 链路是四层，漏一层就断

```
renderer 调用 → src/preload/index.ts 暴露 → src/main/ipc.ts handler → 业务模块
                                                ↓
                                    src/shared/types.ts 补类型
```

新增一个能力要**四处同改**。只改一部分会出现"typecheck 过了但功能不通"的假象。

命名统一 `域:动作`，例：`library:pick`、`window:setFullScreen`、`clip:searchText`。

## SQLite 约定

- 用 better-sqlite3 的**同步** API，不要包成 Promise。
- 建表一律 `CREATE TABLE IF NOT EXISTS`；迁移必须**幂等**（用户会跨版本升级，老库要能直接用）。
- `embeddings` 表是 `PRIMARY KEY (item_id, model)` **双主键**——多模型向量共存是设计意图，不要改成单主键。
- 这个 app 不删用户照片。只有用户明确点"删除"且经确认，才动 `items` 及其文件。

## 模型文件（踩过的坑）

`src/main/clip/models.ts` 的 `candidates()` 最后一条兜底是 `app.getAppPath()/models`，那是**开发期**路径。

判断"模型可用吗"一律用 `resolveModelDir()`，**不要自己拼路径**。真实用户装包后必须走下载流程，开发期能跑通不代表用户能跑通。

## 不要改坏主题变量

`:root` 里的 `--lb-*` 是灯箱的**深色默认值**，会被 `light` / `paper` 皮肤覆盖。

灯箱要固定黑底时用 `.lightbox-fixed-dark` 类（`styles.css:350`），**绝不能改 `--lightbox` 全局值**——主界面其他位置也在用它。

## 长任务要可中断

索引、导入、导出这类跑几十秒以上的任务，必须有：进度回调、取消入口、失败逐条记录（不要把整个任务当一次 try/catch）。


## 双端差异：平台判断只走 `platform.ts`

`src/main/platform.ts` 有明文铁律：**平台差异只在这里出现一次，业务代码一律 import 常量，不要散落 `process.platform`。**

用 `isMac` / `isWindows` / `modLabel` / `altLabel`。自查：`grep -rn "process.platform" src/` 在业务代码里应为 0 处。

改以下位置必须显式回答「Mac 上是什么样」：

| 差异点 | Windows | macOS |
| --- | --- | --- |
| 窗口按钮 | `titleBarOverlay` 三键（右上） | 红绿灯（左上），`trafficLightPosition` |
| 标题栏禁区 | 右侧 **148px** 不放可点元素 | 左侧 **78px** 死区 |
| 沉浸隐藏按钮 | 只能改 overlay 颜色（`symbolColor` 与底色同色） | `setWindowButtonVisibility(false)` |
| 快捷键文案 | `Ctrl` | `⌘`（走 `modLabel`） |
| 关闭窗口 | 关窗即退出 | 关窗不退（`if (!isMac) app.quit()`） |
| 打包 | `npm run dist`（NSIS） | `npm run dist:mac`（dmg + 签名公证） |

无 Mac 真机时，交付里写「静态检查通过，未实机验证」，**不许默认"应该一样"**。
