# 界面与样式规范

## 颜色一律走变量

Tailwind v4 + CSS 变量。颜色写 `bg-[var(--panel)]`、`text-[var(--faint)]`、`border-[var(--border)]`。

**禁止硬编码** `#FFF`、`bg-white/8`、`text-black`。历史遗留的写死色在浅色皮肤下会直接失效——灯箱左右箭头曾经用 `bg-white/8 + text-white/80`，在米色背景上几乎看不见。

## 四套皮肤都要看

`src/renderer/src/styles.css` 有 5 个变量块：`:root`（深色默认）/ `light` / `night` / `paper` / `contrast`。

改配色或对比度：四套皮肤各看一眼，并跑 `npm run check:contrast`。

## 整页视图 vs 模态弹窗（z-index 与标题栏）

自定义标题栏 `TitleBar` 高 **36px**、`relative z-40`。

| 类型 | 写法 | 说明 |
| --- | --- | --- |
| **整页视图**<br>（如交付页 `PickDelivery`） | `fixed inset-x-0 bottom-0 top-9` | 必须让出 36px 标题栏 |
| **模态弹窗**<br>（z-50 以上带 overlay） | `fixed inset-0` | 盖住标题栏是合理的 |

写 `fixed inset-0` 做整页视图会被标题栏遮掉 36px，页面自己的 header 只剩一截——这是已经踩过的 bug。

## Windows 原生三键挡不住

`titleBarOverlay` 是**操作系统层**，画在网页之上。网页里任何 z-index 都盖不住它。

要"隐藏"只能：改它自己的颜色（`win.setTitleBarOverlay({ color, symbolColor })`）或进全屏。**不要试图用 CSS 解决。**

## 无障碍：不许用 inert / aria-hidden 隐藏控件

控件"自动隐藏"时只能用 `opacity` + `pointer-events-none`，**保持 DOM 结构和 a11y 树**。

用 `inert` / `aria-hidden` 等于把功能从 Tab 序列和读屏里删掉——这是硬伤，不是优化。

键盘可达性靠 `:focus-within`：一聚焦就整条浮出，并冻结自动隐藏计时。

## 分界线只留一条

每处分界只能有一个来源：栏的 `border` 或拖拽手柄的线，**二选一**。

两条 1px 线夹一个间隙会读成"凹槽 / 双描边"，浅色暖调下尤其脏。

## 沉浸态交互（灯箱）

- 主触发是**上下 68px 边缘带**，不是任意 `pointermove`（看片时手会抖，一抖就弹出一堆字，比常显更烦）。
- 透明度三档：静止 `.38`（下限）/ 触发 `.72` / hover `1`。
- 动效只做 `opacity`，不做位移、缩放、回弹。

## 控件密度

一个工具条超过 7 个可见控件就要分组或收进二级。摄影用户看片时注意力应该在照片上，不在控件上。


## 四种状态都要设计

每个界面、控件、状态条都要想清楚 **空态 / 加载中 / 错误 / 超长内容**，不能只做"有数据"那一种。

**没有数据时不要显示占位符垃圾**——没器材信息就整条不渲染，别留 `f/— — ISO — 没有器材信息`。

## 对比度具体数值

| 状态 | 最低对比度 |
| --- | --- |
| 静止态文字 | **≥3:1** |
| 交互 / 聚焦态 | **≥4.5:1** |

改完跑 `npm run check:contrast`。不能只靠颜色区分状态，要叠加形态变化（粗细、下划线、图标）。

## 长内容

文件名、文件夹名、镜头名都可能是超长的。一律 `truncate` + `title` 兜底，不要让文字把布局顶破。
