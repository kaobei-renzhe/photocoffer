# 测试与脚本规范

## 测试怎么切

**纯逻辑抽成独立文件再测**。例：`src/renderer/src/lib/chromeVisibility.ts` 只管一个状态机，9 行也能被完整覆盖。

不要把 React 组件整体挂载来测逻辑——慢、脆、还容易测成"实现细节"。

## 改了行为就要改测试

改动状态机、筛选、排序、导出、分类这类纯逻辑，**必须同步更新或新增用例**。

`npm test` 全绿才算完。不要说"应该没问题"。

## 基准脚本（不是单测）

`scripts/bench*.mjs` 是性能实测，跑法：

| 命令 | 测什么 | 耗时 |
| --- | --- | --- |
| `npm run bench` | 导入 / 查询响应 | 约 1 分钟 |
| `npm run bench:clip` | 语义检索（造 5k/30k/60k 向量库） | 数分钟 |

这些脚本会用 `%APPDATA%` 下的**临时** userData，不要把 `BENCH_USER_DATA` 指向真实用户数据。

## 截图自检

`.cache/shot-*.cjs` 用 Electron offscreen 截图。

**必须加 `env -u ELECTRON_RUN_AS_NODE`**，否则 electron 会以 Node 模式启动，截出来是空白图：

```bash
env -u ELECTRON_RUN_AS_NODE ./node_modules/.bin/electron .cache/shot-xxx.cjs <html> <out.png>
```

## 实测优于猜测

涉及性能、准确率、对比度的结论，**跑一次再下判断**，不要凭经验估。

例：语义检索的相似度分布实测是 top1→top500 只衰减 9–15%，凭直觉定的"阈值 0.8 算匹配"会直接失效。
