# 月相 / Lunaris 品牌审计与重构方案

> 审计对象：`D:\trae_projects\lunaris`（Electron 45 + React 19 + Tailwind 4）
> 状态：Logo / 配色 / 字体 / 设计语言部分定稿；**命名部分因用户要求"完全大改"正在重出**
> 日期：2026-11-14

---

## 一句话结论

**它把每一张安全牌都打对了，所以长得像所有同类产品。**

「月相 + 深色底 + 紫色强调 + 系统字体 + 三栏密集布局」= 2024–2026 年通用开发工具的标准脸。没有一处视觉是「只有这个产品才有」的。

真正的病根不是执行质量，是**品牌预算花错了地方**：101% 的设计精力用于"让界面自己更好看"，而产品**唯一被外人看见的页面（客户选片页）完全白牌**。

## 一、Logo：问题不是"细节太多"，是几何错了

### 1.1 硬测算：为什么 16px 一定糊

现行 `build/icon.svg` 由四层构成：渐变底、mask 挖出的月牙、4 个白色星点、两个径向光晕。逐层还原到真实像素：

| 元素 | 512px 下的实际尺寸 | 32px 时 | 16px 时 | 结论 |
|---|---|---|---|---|
| 4 个星点（r=4 / 2.6 / 2.2 / 2） | 直径 8–4px | 0.5–0.25px | 0.25–0.12px | **全部低于 1 像素** |
| 月牙光晕（#7B5CE8 @42%） | 半径 230px | — | — | 只剩一层脏底 |
| 1.6px 描边环 | 1.6px | 0.1px | 0.05px | 直接消失 |
| **月牙最薄处（尖端）** | **14.1px** | **0.87px** | **0.44px** | **糊成 D 形实心块** |

**关键点在第 4 行**：月牙本身是"两个圆相减"的产物，尖端必然收成一条楔形。14.1px 的最薄处在 32px 时只剩 0.87px——**不到一个像素**，抗锯齿一平均就变成灰色噪点。所以 16px 下它不是"看不清细节"，是**整个形状塌成一团**。

> 这不是"细节太多"的问题。就算把星点全删掉，只要形状本身是"渐收的楔形"，到 16px 就必然失效。**形状的几何属性决定了它的下限，跟精细程度无关。**

### 1.2 当前图标的三重问题

1. **小尺寸必死**：见上，几何决定的，不可通过微调挽救
2. **指向错误功能**：月牙 + 深紫 + 星点 = 睡眠 App / 夜间模式 / 天气 App 的通用符号。跟"管照片"零关联
3. **资源浪费**：名字叫「月相」，本意是一套 8 个相位的状态序列，但图标只用了「一弯月牙」这一帧——最俗的那一帧

### 1.3 四个可落地母题（按可靠度排序）

#### M1 · 取景框 + 相位圆 ★推荐
- **几何构成**：外层 4 个圆角 L 形实心块（四角框，各约 80×80px、圆角 24px），内层 1 个实心圆（直径约 210px）用一个偏心圆减去一块，形成"被咬掉一口的圆"
- **为什么抗缩放**：一共只有 **5 个实心块**，全部是凸多边形/圆形，没有任何楔形、渐变、发光。缩到 16px 时四角框仍有 2–3px 的实心角，圆心亮部仍在
- **语义**：取景框 =「我在挑选」；相位圆 =「这张处在流程的哪个阶段」
- **适配**：深色底 #191C22 + 前景 #F2F3F5；浅色底反色；**单色/黑白打印天然成立**（因为本来就只有黑白两色，无渐变无彩色）
- **砍掉什么**：星点全部不要、发光全部不要、渐变底改成纯色底

#### M2 · 印章框（中国风解法）
- **几何构成**：一个正方形实心底（朱红 #A8321E 或墨黑），内部镂空一个「月」或「片」的负形（负形是关键——留白是实的，字是空的）
- **为什么抗缩放**：**负形印刷**是最古老的抗缩放形式（印章用了两千年）。缩到 16px 时，虽然字看不清了，但"一方红底 + 中间一块空白"的视觉结构仍在，且红黑对比度极高
- **适配**：深色模式用朱红底白负形；浅色模式用墨黑底纸白负形；单色直接印黑
- **风险**：如果负形太复杂（比如"影"字），16px 会糊；建议只用一个极简的「月」或一个抽象缺口

#### M3 · 单帧（极简摄影）
- **几何构成**：一个实心圆角矩形（照片），左上角切掉一个直角缺口（缺口本身是个小三角），缺口里填一个小三角——形成"角标/裁切标记"的暗示
- **为什么抗缩放**：2 个实心块，且刻意做成"不完整"——不完整的形状在小尺寸下反而更容易被记住（大脑会补全）
- **适配**：单色成立；深浅底都行

#### M4 · 负形月（改良版月牙）
- **几何构成**：一个**实心圆**，用另一个实心圆在边缘减去一块——但**不做成尖楔形**，而是让两块都是"钝口"（即被咬掉的那口是圆弧过渡，不是尖锐的角）
- **为什么比现行好**：钝口的月牙最薄处可以做到 40px+（512px 下），32px 时还有 2.5px，能活
- **风险**：仍然是月牙，仍然跟睡眠类 App 撞车。**只有在你决定保留「月」意象时才用**

### 1.4 小尺寸策略（三档降级）

| 尺寸 | 保留 | 删除 | 文件 |
|---|---|---|---|
| 256–512px | 全部元素（框 + 相位圆 + 细节） | — | icon.png |
| 48–128px | 框 + 实心圆 | 任何内部细节、任何光晕 | icon.png |
| 16–32px | **只保留四角框 + 一个实心圆点** | 相位缺口、所有其他元素 | icon.png（手工单独导出，不要靠缩放） |

**铁律**：16/32px 版本必须**手工重画**，不能从 512px 自动缩放。所有专业图标都这么做。

## 二、配色：品牌色应该是无彩色

### 2.1 为什么 `#7AA2F7 → #9C8CFF` 不够

只换蓝为紫，解决的是"撞了 Tokyo Night"这一个问题，但没解决根本问题：

**测算结果**：界面上 `--accent` 的实际使用面积里，**42.7% 花在了"数据"上**（12 组标签色块、文件夹选中底），比品牌出现得更频繁。也就是说：

> 用户看到的"主色"，主要是**标签列表**的颜色，而不是品牌。改一个色相，只是让这一大片色块换了个颜色。

### 2.2 主张：品牌色 = 无彩色

不做蓝、不做紫，做**墨、纸、印**三色。理由三条：

1. **不跟照片争**：照片缩略图是唯一应该饱和的东西。品牌色一旦带彩度，就会跟照片打架；无彩色不会
2. **不跟状态争**：已选/已排除/待交付这些状态必须能被颜色区分。品牌色占掉一个色相，状态就少一个可用色
3. **不跟竞品撞**：Lightroom 是蓝、Capture One 是橙红、Eagle 是紫、Darktable 是红。**没有一家做大工具用无彩品牌色**——这是空位

### 2.3 具体色值

| 角色 | 值 | 用途 | 出现在哪 |
|---|---|---|---|
| **月白**（品牌主色） | `#8B8FA3` | 纯金属灰，唯一的"品牌签名" | 只用在：应用图标边框、启动画面、关于页 logo |
| 墨黑（表面） | `#191C22` / `#12141A` / `#0C0E13` | 三级表面 | 全站 |
| 纸白（文字） | `#F2F3F5` / `#A8AEB8` / `#767D89` | 三级文字 | 全站 |
| **低饱和靛**（功能色） | `#5B6FA8` | 只给「正在处理的长任务」 | 导入进度条、语义索引建立、AI 分析中 |
| **印泥红**（警示色） | `#A8321E` | **只给破坏性操作的最终确认** | 永久删除、清空图库 |
| 琥珀金（星标） | `#D9A54A` | 只给星级和旗标 | 照片评分 |
| 语义绿 | `#4E9A6B` | 只给"成功" | 已保存、已导出 |

**关键约束**：`#5B6FA8` 和 `#A8321E` 各自**只允许出现在一处场景**。一旦某个颜色开始到处用，它就不再是信号，变成了装饰。

### 2.4 主按钮用反色，不用强调色

**做法**：主按钮 = 白底 + 黑字（深色模式下）；浅色模式下 = 黑底 + 白字。

**理由**：这是相机和摄影器材的设计语言（Nikon Zf 的机身按钮是黑底白字、Leica 的菜单是白底黑字）。它同时表达两件事：一是"这不是一个互联网 App"，二是"我不需要用彩色告诉你哪个是主操作"。

**效果**：`#9C8CFF` 那个"加入选片"紫按钮是整屏最响的东西，抢了照片的注意力。换成黑白反色后，**照片重新成为屏幕上最响的元素**——这才是照片库该有的层级。

## 三、字体：现在的字阶是假的

### 3.1 诊断

`--fs-xs: 10.5px / --fs-sm: 11.5px / --fs-base: 12.5px`——三档之间**只差 1px**。

在 1440p（100% 缩放）下，10.5 与 12.5 的视觉差异几乎不可感知。而且全站有 **318 处**硬编码字号。所以现状是：**名义上 3 档，实际只有 1 档**——这就是"界面平"的原因之一：没有层级，所有文字在同一个平面上。

### 3.2 建议字阶（6 档，比例 1.2–1.3）

| Token | 值 | 用途 |
|---|---|---|
| `--fs-caption` | 11px | 元数据、参数、计数（可小，但要够对比度） |
| `--fs-body` | 13px | 正文、列表项 |
| `--fs-body-lg` | 15px | 面板标题、文件名 |
| `--fs-title` | 18px | 页面标题 |
| `--fs-heading` | 24px | 空状态大标题 |
| `--fs-display` | 32px | 仅启动画面 / 关于页 |

**配套**：`--faint` 当前在 7 套主题里全部不达 WCAG 4.5（2.58–3.95），必须提升到 ≥4.5。这是**性价比最高的一条改动**——改一个变量，全站辅助信息从"看不见"变成"看得见"。

### 3.3 字体选择（双轨：界面轨 + 品牌轨）

| 轨道 | 字体 | 授权 | 用在哪 |
|---|---|---|---|
| **界面轨（英文）** | Inter | OFL，免费商用 | 所有 UI 文字、数字、参数 |
| **界面轨（中文）** | 思源黑体 / Source Han Sans SC | OFL | 所有 UI 中文 |
| **品牌轨（标题）** | Newsreader 或 Fraunces | OFL | 启动画面、空状态大标题、关于页 |
| **品牌轨（中文）** | 霞鹜文楷 LXGW WenKai | OFL | 同上，与英文字体气质对应 |

**为什么要有品牌轨**：现在全站只有一条 `'Segoe UI', 'PingFang SC', 'Microsoft YaHei', system-ui` 系统字体栈——这是"工程师默认设置"，等于放弃了一块品牌资产。品牌轨只在 **3 个地方**使用（启动、空状态、关于），成本极低，但能让产品有"被设计过"的痕迹。

**注意**：中文文楷在 13px 以下会糊，所以品牌轨**绝不能用于 UI 正文**。

## 四、设计语言：三个错误的根源 + 一条主张

### 4.1 现行界面的 12 条具体缺陷

| # | 问题 | 量化 |
|---|---|---|
| 1 | 品牌色 42.7% 用在数据上 | 见 2.1 |
| 2 | `--faint` 全线不达标 | 7 套主题 2.58–3.95，标准 4.5 |
| 3 | 相邻表面明度差不足 | 多处 1.021–1.085，经验值需 ≥1.10 |
| 4 | 表层实际有 8 种，超出认知 | 用户能稳定分辨 ≤4 种 |
| 5 | 6 个模块 6 种色相 | 紫/绿/琥珀/红无主次 |
| 6 | 字阶只差 1px | 见 3.1 |
| 7 | 318 处硬编码字号 | 无法统一调整 |
| 8 | 圆角只有 2 档 | 相机镜头是真圆，界面却全圆角 |
| 9 | 两套灰并存 | TDesign 蓝灰 + Tokyo Night 蓝白 |
| 10 | 缩略图被裁成正方形 | 摄影师默认构图被系统裁掉 |
| 11 | 6 套皮肤像应用商店 | 把品牌决策推给用户 |
| 12 | 客户选片页完全白牌 | 唯一的对外页面，零品牌 |

### 4.2 一条核心主张

> **品牌预算从"界面装饰"整体挪到"决定性瞬间"。**

摄影里有个词叫决定性瞬间（The Decisive Moment）——产品里也有它的决定性瞬间：**客户第一次打开选片链接的那一刻**。那一刻客户看到的不是 UI，是你的品味。而现在那个页面是白牌的。

**所以**：界面本身越安静越好（无彩、低调、不抢照片），把省下来的全部注意力投到 3 个地方：
1. **应用图标**（用户每天在任务栏看 50 次）
2. **启动画面**（第一次打开时的第一印象）
3. **客户选片页**（唯一被外人看到的页面）

### 4.3 状态语言：相位系统（绑定旧名，需随命名重设计）

| 状态 | 原生月相名 | 形状 | 填充 |
|---|---|---|---|
| 未处理 | 新月 | 空心圆环 | 0% |
| 已评星 | 上弦月 | 右半实心 | 50% |
| 待交付 | 盈凸 | 3/4 实心 | 75% |
| 已交付 | 满月 | 实心圆 | 100% |
| 已排除 | 月食 | 实心圆 + 斜杠 | — |

**为什么这套成立**：它是**明度编码**而不是颜色编码——灰度化、色盲、黑白打印全都可分。而且竞品没有（Lightroom 用旗标、Capture One 用颜色标签、Eagle 用星）。
**注意**：这套系统绑定「月相」这个名字。换名后需要用同样的逻辑重新设计一套（等命名定稿）。

### 4.4 皮肤：从 6 套砍到 3 套

**保留 3 套**：深色（主）/ 浅色（备）/ 高对比（无障碍）
**砍掉 3 套**：月蚀、夜航、柔光（这三套只是换色，且各自跟某个已有产品撞车）

**理由**：6 套皮肤不是功能，是**品牌决策的负担转移**——把"这个产品该长什么样"的问题推给了用户。3 套以内是产品（深/浅/无障碍），超过 3 套是主题商店。

## 六、命名（待补）

**状态**：因用户要求「完全的大改」，且三个方向（中国风/水墨、摄影本体、功能直连）被澄清为"灵感来源非必选清单"，命名候选正在重出——将提供 8–11 个中英配对，含跳出三桶的思路（纯功能 / 造词 / 英文优先）。

**已确证的撞车事实（供决策参考）**：

| 名字 | 撞车情况 | 结论 |
|---|---|---|
| 月相 | App Store 有《月相：月历与月球追踪》（天气类） | 已被占 |
| Lunaris | App Store 有 `Lunaris: Super Zoom Camera`（摄影与录像类，2026-05 上线） | 直接同业撞车 |
| 留白 | App Store 有《留白相册》（本地 AI 查重 + 离线 + 滑动整理，**功能高度重合**） | 同赛道撞车，建议淘汰 |
| 明室 | 中文未查到占用；罗兰·巴特摄影理论经典《明室》（La Chambre Claire）同名 | **干净且有文化纵深，重点候选** |

**语义方向问题**：摄影圈里「月相」= 月亮相位规划工具（PhotoPills 生态）。一个摄影师看到这名字，会以为这是"什么时候拍月亮"的辅助 App——**名字指向了错误的功能预期**，这比"不够独特"更严重。

**命名演进史**：`image-nest`（功能极清晰）→ `月巢`（开始诗意）→ `月相/Lunaris`（完全诗意化）。每一版都在往"更好听但更猜不出干什么"的方向走。
