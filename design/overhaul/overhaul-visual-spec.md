## 1. 色彩定调：三个摄影方向 + 推荐

### 1.1 先钉住 accent 的职责（沿用 v1，不改）

`--accent` 只承担**一个**语义：**「系统回应你」**（选中 / 聚焦 / 链接 / 进行中）。它不承担「哪个按钮更重要」（那是主按钮反色的事），也不承担「你标记了照片」（那是 `--star` 暖黄）和「不可逆」（那是 `--danger` 珊瑚红）。

新增一条面积纪律 **P1′**（比 v1 的 5% 更严）：
- 单个 accent 填充元素 ≤ **120×32 px**；
- 单屏 accent 总面积 **< 3%**；
- accent **禁止以「面」出现**，只允许「线（1–2px）/ 点（≤6px）/ 字 / 环（outline）」四种形态。唯一例外是 `--accent-soft` 选中底（低彩度，不算「面」）。

### 1.2 蓝为什么「普通」——三条可证伪的理由

1. **行业占位饱和**：Lightroom / Photoshop / Bridge / Apple Photos / Affinity / Snapseed 的 accent 全是蓝（`#31A8FF` 到 `#147EFB` 一条带）。蓝在此品类里等于「没选」。
2. **与内容抢色**：照片里高频高饱和色相第一是天空/水的蓝（H≈200–215，正是 `#5B9FE8` 的 H≈210）。UI 蓝与缩略图蓝同频，选中环在小图上会被照片吞掉——这是 v1 的物理缺陷，不是审美问题。
3. **场景错位**：摄影的原初空间是暗房，暗房里没有蓝光——只有安全灯的**红/琥珀**和药液的**琥珀**。用户对「摄影味道」的记忆锚点是暖光，不是屏幕蓝。

### 1.3 已占位色相 & 空位分析（找空位，不撞现成）

| 色相区间 | 谁占了 | 存照能不能去 |
|---|---|---|
| H 200–215 蓝 | 全行业 + Lightroom + Apple | ❌ 主人已否 |
| H 20–30 橙 | Capture One（橙红填充）、ON1、DxO | ⚠️ 可用，但**只能做线不能做填充**，否则撞 C1 |
| H 8–12 红 | Darktable、v1 的 `--danger` 珊瑚红 H≈8 | ❌ 语义已被「不可逆」占死 |
| H 280–310 紫 | Eagle、旧 eclipse 皮肤（已砍） | ❌ 像设计工具，不像相机 |
| H 120–160 绿 | 无（但 `--success` 已占语义） | ❌ 两个绿比两个橙更糟 |
| H 36–42 金 | v1 的 `--star` 暖黄 `#F5C344` | ❌ 已被「你标记的照片」占死 |
| **无彩（银/石墨）** | **无（Leica/Nikon 菜单是黑白，但没人把它做成 accent token）** | ✅ **空位** |
| **H 24–30 琥珀（低彩度、细线）** | **无（C1 是高彩度填充橙，不是琥珀线）** | ✅ **空位** |

结论：**空位有两个——「无彩银」和「琥珀线」。** 三个方向就落在这两个空位 + PA2 自身退化方案上。

**新增第四色？是，但它不是「第四张照片」，是「光」。**
- 物理出处：安全灯（H≈25–30）、钨丝灯 2800K、胶片边码橙、黄铜氧化。
- 与 PA2 不同层：PA2 三色 = 被照的**内容**；琥珀 = 照在上面的**光**。规则上永不同框并列（沿用 v1「三色禁止装饰性并置」，琥珀不受限但只准「线/点/字/环」）。
- 因此 P3 修正为 **P3′：UI 色值必须能在「PA2 材料」或「光」两个出处之一里找到；「光」只允许一个 hue（H 24–32），不允许再加。**

**风险与适用性**
- ✅ **不与照片抢色**：照片里琥珀多是肤色（S 20–40% 低彩度）与夕照；UI 琥珀是 S 73% 的 1px 线，且**chrome 永远不压在照片上**（条占布局，见 5.1）。反例必须硬禁：**照片上的圈选框（note region）不得用 accent**，改用亮框银 `#F2F5F8` + 1px `rgba(0,0,0,.45)` 外描边（`Lightbox.tsx` `RegionLayer` 现在是 `var(--accent)` 边框 + 14% accent 填充，必须改）。
- ⚠️ **三个暖色并存的压力**：琥珀(H28) / 暖黄(H41) / 珊瑚红(H8) 同屏时浪费辨识带宽。对策：`--warn` 收敛为 accent 族（见附录 A），并在任何视图里**暖黄只允许以「实心五角星/旗标」出现，珊瑚红只允许在最终确认层**，两者都不与琥珀线同处一行。
- ⚠️ 与 Capture One 的区分靠**形态**不靠 hue：C1 的橙是按钮填充与大色块；存照的琥珀永不填充、宽度 ≤2px。
- ✅ 色觉障碍：deuteranopia 模拟下琥珀→黄绿（明度保留），与珊瑚红（→黄）仍靠 **30 的明度差 + 形态差（线 vs 实底按钮）** 区分；且 R3「状态必须 icon/文字冗余」不变。
- ⚠️ 暗底上 `--accent-soft` 呈暖褐（`#3D2D22`），必须靠 R2 四件套里的 2px 指示条承担主信号，soft 只做辅助底——这条在本方向比在天蓝下更重要（褐底不与任何东西「看起来像选中」）。

> **它让 App 像什么**：镜头卡口上那一个对位红点。整台机器只有这一点红，但它决定一切能不能装上。

- **适用性**：品牌一致性最强，语义风险最大。只有当主人说「我不想加新颜色」时才选。

### 1.7 三方向一句话对比 + 推荐

| | 一句话 | 像什么 | 与 PA2 | 新增色相 | 迁移成本 | 风险 |
|---|---|---|---|---|---|---|
| **A 安全灯** | 黑房里的一盏琥珀灯 | 暗房 / 钨丝 / 黄铜 | 蓝退出，黄红不动，+1「光」 | 1（H28） | 中（6 accent + 3 warn + 1 focus 值 + swatches） | 三暖并置、被误读像 C1 |
| B 亮框 | 只留亮线，颜色全给照片 | 旁轴取景器 / 高端仪器 | 三色全退出 UI | 0 | **最低** | 太素、状态同化 |
| C 镜位红点 | 整机只有一个红点 | 镜头对位点 | 零新增 | 0 | 中（且要动 danger 语义） | 与「危险」同色、撞 C1/darktable |

**推荐 A，理由四条：**

1. **只有 A 解释了「存照」这个词**：影是光画的。三张照片需要一个光源，天蓝不是一个光源，琥珀是。
2. **A 修掉了蓝的物理缺陷**：蓝与照片里的天空同频；琥珀在照片里出现的彩度远低于 UI 的 1px 线，且 chrome 不压图（5.1）。
3. **A 保住品牌一致性**：蓝没有「消失」，它只是回到了它唯一该在的地方——Logo。UI 里剩下的黄/红本来就是「一色一职」里的两个动词，它们不需要蓝作伴（v1 早已禁止三色并置装饰，所以不存在「视觉断层」）。
4. **A 同时提供结构，不只提供颜色**：琥珀逼出一个「线/点/环」的形态纪律（P1′），这套纪律本身就把界面从「Web App」推向「器材」。B 的克制可以后补（选中态用 2px 亮线而非色块——A 已经吸收了这一点）。

> **若主人仍觉得 A 太暖**：B 是**只改一张表**的备选（token 契约完全相同），不需要重做任何组件。这一点请 UX 在验收时明确告知，降低决策成本。

## 1A. 色彩定调·第二批（胶片工艺族）

> 背景：第一批 A（琥珀·灯光）/ B（银·器材）/ C（红·器材）被主人**全部否决**，未给具体偏好。
> 复盘：三个方向虽然色相不同，但**出处词汇相同——都在「器材与灯光」里打转**（暗房的灯、取景器的框、卡口的点）。如果主人不喜欢的不是某个颜色而是这套词汇，换色相没用，要换出处。
> 第二批规则：**只从「摄影工艺与胶片文化」选族**——胶片盒、印相工艺、手工相纸；不再出现灯、框、点。

### 1A.1 方向 D｜「胶卷盒」——富士青绿（**第二批推荐**）

### 1A.4 三方向对比 + 推荐

| | 一句话 | 摄影出处 | 色相 | 语义合并 | 迁移成本 | 主要风险 |
|---|---|---|---|---|---|---|
| **D 胶片青绿** | 抽屉里那排没拆的富士卷 | 富士 C200/Superia 包装绿 | H156（软件空位） | success 并入 accent | 中（6 token + success + swatches，warn 还原） | 与植物同族、「绿=通过」语境、色觉最不友好 |
| E 蓝晒靛蓝 | 印在纸上的蓝，不是屏幕射出的蓝 | cyanotype 1842 / 蓝图 | H211 低彩 | 无（全部保留） | **最低** | 结构上仍是蓝，若否的是色相则直接出局 |
| F 铂盐暖黑 | 有温度但没有颜色 | platinum print 1873 | H41/31 极低彩 | 无（全部保留） | 低 | 「B 的暖色版」，可能再次嫌素 |

**推荐 D，理由五条：**

1. **三批否决的交叉排除**：暖（A）否、无彩（B）否、红（C）否、蓝（旧）否——色相盘上**没被否过又没被占用的，只剩绿/紫/青三段**；其中紫色已被判「像设计工具」，青色撞 Luminar，只有绿同时满足「未踩雷 + 有强摄影出处」。
2. **出处是内容侧而不是器材侧**：A/B/C 讲的是「拍照的机器」，D 讲的是「等待被拍的照片」——主人做的是照片管理 app，内容侧词汇命中率更高。
3. **软件空位可验证**：没有一个主流摄影/选片软件用绿作 accent（LR 蓝、C1 橙、Eagle 紫、ON1 蓝、Luminar 青、darktable 红、Apple 蓝）。
4. **语义红利**：success 并入 accent 后，「绿 = 系统与你的照片之间的一切良性回应」成为单一语义，比蓝/琥珀方案少一个颜色家族。
5. **风险全部有量化对策**（H156 与植物绿的 25–55° 缝、deuteranopia 模拟下的 18 明度差兜底、✓ 图标形态分离）。

**给主人的备选顺序：D → F → E**（E 放最后不是因为差，而是它能否成立取决于主人否蓝的粒度，这个信息我们现在没有）。

> **看图工具**：三方向的可切换高保真 mockup 在 `design/mockups/overhaul-mockup.html`（顶部 D/E/F 切换，三个真实场景 + 规范标注开关），用浏览器直接打开即可。
>
> **如果 D 也被否**：请停止在「色」上继续枚举——三批 6 个方向已覆盖色相盘上全部可用空位（暖/无彩/红/绿/蓝/暖黑）。下一步应该换维度：把决定权从「色值表格」换成「两张高保真 mockup」（D 与 F 各一张真实界面上色图），让主人**看图选**而不是读表选。文字已经被证明无法传达「调性」，图可以。

### 1B.0 两套语法对照（诊断，不是审美争论）

| 维度 | 器材语法（A–F 的假设） | 作品语法（参考 App 的做法） | 对应 G 的做法 |
|---|---|---|---|
| 界面角色 | 界面是一台机器，照片是唯一有颜色的东西 | 界面是一张托底的桌子，照片是主角 | 照片面积 +65%，界面退到边缘 |
| 分隔 | 1px 实色线划边界 | 底色分档 + 留白 | 主窗口 **零结构线** |
| 形态 | 线 / 点 / 字 / 环，禁止面 | 面（填充）+ 大圆角 | accent 以面出现，圆角 8/12/16/20 |
| 圆角 | 8 / 11 两档，接近直角 | 12–20，摸得到的软 | 五档圆角阶梯 |
| 深浅 | 冷蓝黑 `#14161B` + 冷白 `#E8EEF4` | 暖近黑 `#171818` + 纸白 | 暖黑 / 暖纸 |
| 高度 | 不投影，hover 只提亮 | 软阴影，卡片微微浮起 | 三档暖调阴影 |
| 层级 | 字阶三档只差 1px，靠留白 | 粗标题 + 细正文，字重拉层级 | 六档字阶 + 400/500/600/700 |
| accent 职责 | 只表示「系统回应你」 | 品牌色 = 功能色 = 手能点的地方 | accent = 可点/已选/进行中，**允许填充** |

| **醒图**（移动修图） | 浅底、扁平、**粗标题 + 细正文**、底条工具 + 大预览、slider 实时 | ★★ 借「浅色 + 字重分层 + slider 面语言」，**不借底部 Tab** |
| **光影边框**（胶片边框工具） | 暖纸、齿孔、**「照片被装进画框」**的隐喻 | ★★ 只借「包住照片」这一件事：matte / 留白 / 软阴影 |

**三处补充（brief 没写但对结论有用）：**

1. **三个 App 的底层只有一条**：照片面积 ≥ 60%，UI 全部收缩到边缘。配色只是这条的副产品——所以「换色」永远解决不了它。
2. **PixCake 的「专业感」不来自黑，来自「低饱和 + 单色 + 零装饰」**。它的近黑是 `#171818`（S≈0），不是纯黑 `#000`：纯黑会让照片的暗部失去参照、看起来发灰。这条直接决定 1B.3 的裁决 1。
3. **醒图的教训比它的配色重要**：品牌绿 `#AFF51E` 在它的界面里几乎不出现——**品牌色 ≠ 功能色**。但暖黄 `#FDC75D` 对近黑是 11.44:1，可以同时当品牌色和功能色，这是 PixCake 比醒图高明的地方，也是我们该学的：**一个暖黄，从头用到脚，不引入第二个彩色。**

**两处修正（brief 的推断需要校准）：**

- **修正 1**：「iPad 上侧跳转区（返回/个人中心/导出）」在桌面上**不对应顶部 Tab**，对应的是「标题栏 36px + 一条 48px 工具条」——因为桌面没有「返回上一页」这个动作。照搬会得到一条无意义的 Tab 条。
- **修正 2**：「下侧缩略图条」在桌面**不该进主结构**。桌面三栏已经有侧栏承担导航，再压一条底缩略图会变成四边围合（参考 App 是移动端手势导航，没有侧栏才需要底条）。它只在**查看器内部**有意义（胶片条），归 Phase 2 UX 决定。

### 1B.3 色彩

**先给六条裁决，再给 token 表。**

**裁决 1｜近黑用 `#171513`，不是 `#171818`，也不是 `#14161B`。**
`#171818` 是纯中性（S=0）。它与暖黄 `#FDC75D` 大面积相邻时，人眼会因同时对比把中性底色读成**微绿灰**——这是我们在 A 方向就验证过的现象。把底板压到 H≈34° / S≈9% / L≈8.6% 的**暖黑**，黄才读起来像「灯」而不是「贴纸」。
代价：偏离了 PixCake 的原始值。**如果主人更喜欢中性**，把 `--bg` 换回 `#171818`、`--chrome #1C1C1E`、`--panel #222224` 即可，其余 token 不动（这是唯一一处允许的替代）。

**裁决 2｜文字用暖白 `#F3EEE4`，不用 `#FFFFFF`。**
纯白在暖黑上是「屏幕白」，暖白才是「纸白」。实测对 bg 15.75:1，从 15.75 掉到 15.75 以下没有可读性收益，但观感差别很大。

**裁决 3｜`--star` 并入 accent 族（两色必撞，无法共存）。**
实测 ΔE76：`#FDC75D` vs 旧星标 `#F5C344` = **8.8**（ΔE<10 视为同色），`#FFC44D` vs `#F5C344` = **4.7**（几乎完全重合）。所以不是「要不要合并」，是「不合并就会有两个一模一样的黄」。
**合并后靠形态区分，不靠颜色**：
- 星标 = **实心五角星贴纸**，画在照片上，带 `0.75px rgba(0,0,0,.45)` 描边 + 1px 投影（这条是必须的：暖黄在白色照片上只有 1.56:1，靠描边才有形）。
- 选中 = **填充底 + 勾**（在容器上，不在照片上）。
- 两者不会同框混淆：星标只出现在照片上，选中只出现在容器上。
**兜底**：若主人仍觉得混，星标改「无彩白 `#FFFFFF` + 深描边」，不新增色相。

**裁决 4｜`--warn` 退出彩色，改「`--text` + 三角图标」。**
黄已经是 accent 了，橙 `#E58B3C` 与 `#FDC75D` 的 ΔE 会落在 10–15 之间（同一族），而 `--danger` 珊瑚红 `#F0664E` 与 accent 的 ΔE 是 **52.6**（可共存）。所以：**黄给交互，红给错误，警告没有第三个暖色可用**——降级为「白字 + 三角图标 + 文案」，符合 R3 冗余要求。

**裁决 5｜`--success` 并入 accent 族（`✓` 强制）。** 界面里不允许出现第二个绿色。这与 1A 的 D 方向同构，是「一屏一个彩色」原则的必然结果。

**裁决 6｜`--danger` 保留，但压暗一档**（G1 `#F0664E`，对 bg 5.82:1；G2 `#C0342A`，5.17:1）。原来的 `#F2604A` 在暖底上偏亮、偏粉。

**新增 `--accent-strong`（G2 专用，重要）**：亮黄 `#FFC44D` 对暖纸底只有 **1.47:1**，做装饰面可以，做 6px 细形状（进度条 / slider）和聚焦环**不合格**（WCAG 1.4.11 要求 3:1）。所以浅色主题拆出 `--accent-strong #A66C00`：对 bg 4.09:1、对进度轨道 3.19:1。

### 1B.4 形状与材质

**圆角五档（`--r-1` ~ `--r-pill`）**

| token | 值 | 用途 | 禁止 |
|---|---|---|---|
| `--r-1` | 8px | 勾选容器、徽标内圈、微型控件、颜色色块 | 卡片 |
| `--r-2` | 12px | 按钮、输入框、图标热区、列表行、分段容器内项 | 大面板 |
| `--r-3` | 16px | 卡片、缩略图、面板、侧栏选中块、右侧模块卡 | chip（用 pill） |
| `--r-4` | 20px | 浮层：菜单、popover、抽屉、toast | 缩略图 |
| `--r-pill` | 999px | chip、标签、进度条、slider、勾徽标、悬浮胶囊条 | 卡片 |

**规则**：只允许这 5 个值，禁止 `4 / 6 / 10 / 14px` 中间值——圆角不统一比不圆更难看。

**阴影三档（暖调，不是黑）**

阴影的 RGB 必须是暖灰（`122,96,56` 系），用纯黑在暖纸底上会发灰、发脏。

```css
/* G1 深色：暖黑阴影 */
--shadow-1: 0 1px 2px rgba(12,9,5,.45), 0 3px 12px rgba(12,9,5,.30);   /* 卡片静置 */
--shadow-2: 0 8px 24px rgba(12,9,5,.45), 0 20px 48px rgba(12,9,5,.30); /* 卡片 hover / 浮起 */
--shadow-3: 0 12px 32px rgba(8,6,3,.55), 0 32px 72px rgba(8,6,3,.40);  /* 菜单 / 胶囊条 */

/* G2 浅色：暖棕阴影 */
--shadow-1: 0 1px 2px rgba(122,96,56,.10), 0 4px 14px rgba(122,96,56,.10);
--shadow-2: 0 8px 24px rgba(122,96,56,.14), 0 20px 48px rgba(122,96,56,.10);
--shadow-3: 0 12px 32px rgba(110,86,48,.18), 0 32px 72px rgba(110,86,48,.12);
```

**用法纪律**：阴影只给「浮在别的东西上面的东西」（卡片、菜单、胶囊）。页面结构（侧栏、工具条、状态条）**一律不投影**——那是「贴纸感」的来源。

**材质六条新规则（替代 §2.2 的 R-M1~M5）**

- **R-G1 零结构线**：主窗口内不画 1px 分隔线；分区靠 `--chrome / --bg / --canvas` 三档底色差 + 16–24px 留白。唯一例外：查看器胶囊内的 `rgba(255,255,255,.10)`。
- **R-G2 面优先**：可点/已选容器用「填充 + 圆角 + 600 字」，不用描边。填充色只允许 `--accent`（实底选中）/ `--accent-soft`（弱选中、行选中）/ `--panel-2`（未选中）三选一。
- **R-G3 软浮起**：hover 抬升 ≤1px + 阴影加深一档；**禁止 translateY > 2px**（200 张图会跟着呼吸）。
- **R-G4 圆角五档**：见上表，禁止中间值。
- **R-G5 字重分层**：层级由「字重 + 字号差 ≥1.5px」双通道建立；**禁止用字色变淡做层级**（正文发灰是这套语言最容易犯的错）。
- **R-G6 保留**：R-M5 数字化（`tabular-nums`）、R3 状态图标冗余、R1（`--faint` 不落在 accent 面上）。

### 1B.5 字体与层级（这一条比配色更决定成败）

**字阶（正式推翻 `--fs-xs 10.5 / sm 11.5 / base 12.5`）**

| token | px | 行高 | 字重 | 用途 |
|---|---|---|---|---|
| `--fs-1` | 11 | 1.5（16.5） | 400 | 元数据、计数、EXIF 单位、文件夹路径、卡片浮层文件名 |
| `--fs-2` | 12 | 1.5（18） | 400 / 500 | 辅助说明、状态条、分组标题（500） |
| `--fs-3` | **13.5** | 1.55（21） | 400 正文 / 500 控件 | 列表项、按钮、chip、输入、菜单 |
| `--fs-4` | 15 | 1.4（21） | **600** | 区块标题、面板标题、库名、查看器文件名 |
| `--fs-5` | 18 | 1.3（23） | **700** | 页面标题、工作台标题、空状态标题 |
| `--fs-6` | 26 | 1.2（31） | 700 | 引导/空状态大标题（唯一允许 >20px 的地方） |

**字重四档**：`400` 正文 / `500` 控件与次级强调 / `600` 区块标题与选中 / `700` 页面标题。
**禁止**：正文用 500（中文 500 在多数系统字体上是伪粗，笔画会糊）。

**中文优先字体栈**

```css
font-family: 'Noto Sans SC', 'PingFang SC', 'Microsoft YaHei UI', 'Microsoft YaHei', system-ui, sans-serif;
```

**必须知道的一个坑**：Windows 的微软雅黑只有 **Regular(400) 与 Bold(700)** 两个字重。写 500 / 600 会命中浏览器的**合成加粗**——在同一段中文里，有的字被算法加粗、有的没有，笔画粗细不齐，比不加粗更难看。
两条出路：
- **方案 A（推荐）**：随包内置 `Noto Sans SC` Variable（子集：常用 3500 字 + 拉丁 + 标点，woff2 约 1.2–1.8MB）。Desktop App 本地加载无网络成本，是唯一能真实拿到 500/600 的办法。
- **方案 B（零依赖）**：只用 400 / 700 两档，把「区块标题」改成 `700 + 字号 -1px`，靠字号差补层级。缺点是 600 的「温和强调」表达不出来。

**中英混排细节**

- 中文 `letter-spacing` 一律 **0**。现有 `.section-title` 的 `.08em` 必须删——中文加 0.08em 会散成「一 个 词 一 个 词」。
- 中文行高 ≥ **1.4**；标题类 1.3–1.4，正文 1.5–1.55。禁止 1.2 以下。
- 数字与拉丁用 `tabular-nums`，中文不受影响，可同段共存。
- `--fs-5` / `--fs-6` 可加 `letter-spacing: -0.01em` 收紧字面，`--fs-1` 及以下不加。

**旧值机械映射（给工程）**：`10.5 → 11`、`11 → 12`、`11.5 → 12`、`12.5 → 13.5`、`13(body) → 13.5`、`14 → 15`。所有 `font-weight: 500` 保留（控件），`600` 用于标题与选中，正文默认显式写 `400`。

### 1B.8 查看器：从「占位横条」到「悬浮胶囊」

**这不违反 §5 的结论，而是它的升级。** §5.1 的诊断依然成立：横条占布局 → idle 淡出没有收益只有闪烁。G 的做法是**改形态**：条不占布局了，所以它可以「一直存在」而同时让照片满幅。

**规格**

- 顶胶囊：高 **44**、半径 pill、距视口 14px、`max-width: 62%`、`--lb-chrome` + `blur(18px)`、`--shadow-3`；内容 = 文件名 15/600 + 计数 12 tabular + 2 个图标按钮（32 热区）。
- 底胶囊：两组分开 —— 左「EXIF 卡」、右「工具条」，均 44 高 pill，距边 14。
  - EXIF：`f/2.8` `1/250s` `ISO 400` 用 **13/500**，单位用 11 muted；间距 16；固定宽（40/56/56）**保留**（5.5 换图不抖动条款全部有效）。
  - 工具：图标 18、热区 32、分区间距 8，分隔用 1px `--lb-rule`（唯一允许的线）。
- 照片：`inset 24px`，**照片本身圆角 2–4px**（大圆角会裁画面），G1 加 **2px 白 matte**（`#FFFFFF`，这是「光影边框」的借用：照片被装进画框），matte 外 `--shadow-3`。
- **140×36 原生三键禁区保留**：顶胶囊居中（`left:50%`）时不重叠；窗口 < 900px 时改左对齐，右侧留 152px。
- G2 浅底查看器（纸感派）：`--lb-stage-bg #F4EEE4`，胶囊白、字深。**风险**：浅底会让暗部判断偏亮。若主人常在查看器校曝光，改用 G2b：只把 `--lb-stage-bg` 换成 `#121110`、`--lb-chrome` 换成 `rgba(28,25,21,.86)`，其余不动。

### 1B.9 风险与边界（诚实的那部分）

1. **白平衡锚点（这是推翻 §2.1 的代价，必须承认）**：整屏染暖，用户在存照里判断的白会偏冷。**补偿**：G1 的查看器用**中性黑 `#0E0C0A`**（不是暖黑），判读区不给色偏；主界面暖、看片区中性——这是专业修图软件里唯一站得住的折中。G2 的纸底查看器本身就是另一种取舍，见 1B.8 的 G2b 逃生门。
2. **亮黄面在浅底上边界不足**：`#FFC44D` 对 `#FAF6EE` 只有 1.47:1。所以 G2 的**细形状一律用 `--accent-strong #A66C00`**，实底面靠「深字反差 + 软阴影」被识别，不靠边界；缩略图选中的亮黄环外面再套 1px `rgba(0,0,0,.20)`，否则它压在白色照片上会消失。这条不能让工程「统一用 accent」。
3. **面积失控**：允许面之后，最容易发生的退化是「到处都黄」。硬规则写在 1B.3：一屏最多 1 个实底主按钮 + 1 组实底 chip；填充 >4% 视为 bug。
4. **中文 500/600 字重缺失**：见 1B.5 的坑。选方案 B 就不要写 600，否则整屏笔画不齐。
5. **高 DPI 半像素**：圆角 12/16 在 125%/150% 缩放下会出现 0.5px 毛边。对策：所有圆角/间距用偶数 px；取消 1px 描边（已经取消）；阴影用 `spread 0` 的纯 blur。
6. **与 4 套 skin 的对应**：`classic` / `night` → **G1**；`paper` → **G2**；`contrast` → G1 语言 + 高对比值（`--bg #0A0A0A`、`--text #FFFFFF`、`--accent #FFD97A`）。skin 数量与 id 不变。

### 1B.10 G1 vs G2

**先说框架**：G1 / G2 **不是二选一的两个方案**，是同一套语言的深色版与浅色版——就像现存 4 套 skin 里 night 与 paper 的关系。**真正需要主人决定的是「走不走这套语言」，而不是「深还是浅」。** 建议两者都落，`classic`/`night` 用 G1，`paper` 用 G2。

| | **G1 · 深色（定稿=中性黑，见 1B.12）**（像素蛋糕桌面派） | **G2 · 浅色纸感**（醒图 / 光影边框派） |
|---|---|---|
| 一句话观感 | 黑色机身 + 一盏暖黄的灯，照片摊在上面 | 像把照片铺在一张暖白卡纸上，四周留白 |
| 照片表现 | 照片最跳，彩色最准（暗底不抢） | 照片最「像印刷品」，柔和，但暗部会显亮 |
| 长时间看图 | 更耐看，专业工具的默认 | 白天更轻，晚上会刺眼 |
| 主要风险 | 中性底更「硬」，柔软全靠圆角与字重撑；照片旁的灰阶反差略高 | 亮黄边界弱、暗部判断偏亮 |
| 建议 | **主形态** | **浅色主题（paper skin）** |

### 1B.12 定稿：G-neutral（主人选定）— 深色中性黑

> **决策来源**：主人「走 G 这套语言，但深色就黑色，不要暖调」。
> **本节取代**：1B.3 的 G1 表（暖黑）、1B.11 第 3/4 条的深色值。**G2 浅色纸感一字不动**。1B.4–1B.8（圆角/阴影/字阶/密度/胶囊/面积纪律）**全部不变**——中性化只动色值，不动结构。

#### 裁决 1｜文字转中性 `#F2F2F2`，不用暖白 `#F3EEE4`

1. **文字是屏上面积最大的「颜色」**。暖白会把整个界面重新染暖——等于把刚被否掉的暖调从排印层偷回去。
2. **中性白让暖黄成为屏幕上唯一的暖色**。「一盏灯」的读法不但没变弱，反而更强：暖黑版里灯和桌面同色，灯不够亮；中性版里桌面彻底无色，黄才真的像灯。
3. **判曝光锚点更干净**。chrome 与查看器现在全部中性，屏幕上不存在任何色彩偏置——这比暖黑版更符合「看片软件不能让用户误判白平衡」。

补充：**不用纯 `#FFFFFF` 做正文**（近黑底上会晕光、笔画发胖），`#F2F2F2` 对 bg 15.89:1 已经足够；需要更「亮」时用 **600 字重**，不要提亮色值。

#### 裁决 2｜阴影也去暖（最容易被漏改的一处）

暖黑版阴影是 `rgba(12,9,5,…)`（暖黑调成的影子）。在纯中性底上它会让卡片边缘泛出脏棕，必须改成纯 `rgba(0,0,0,…)`。

### 1B.13 与人像工作台的接口（对齐 UX 1.2.4 / 1.4 / 1.5）

> UX 纠出 mockup 右栏的一处**内容错误**：那里原本是「人像调节」（磨皮/肤色/眼神光/亮度滑杆 + 预设）——那是**像素蛋糕的本职（人像精修）**，而存照全库**不写回任何像素**，照搬会得到一排点了没反应的滑杆。
> **裁决（同 UX）**：右栏**容器全部沿用**（252 / 16 / `--panel` / `--shadow-1` / padding 16 / 行距 14），**内容换成选片动作**。这是「结构借鉴、内容不搬」，与 1B.7 的映射表一致。本节补三样东西：状态卡（新组件）、动作卡的视觉规格、两处既有裁决的修订。

#### 1B.13.1 人像状态卡（左栏新组件，视觉定义）

**位置与外壳**

| 项 | 值 | 说明 |
|---|---|---|
| 位置 | 左栏顶部，`position: sticky; top: 0`（外层 wrapper 给上 6 / 下 12 内边距，避免阴影被裁） | 常驻不可折叠——它是识别纠错入口，也是「专注感」的来源 |
| 容器 | **`--card` 底 / 圆角 16 / padding 10 / `--shadow-1` / 无描边** | 见下面「为什么不完全同意用 --panel」 |
| 行高 | **38px**（与 `.side-item` 一致，左栏只允许一种行高） | UX 建议 38，采纳 |
| 行内 | `padding: 0 10px` / 圆角 8 / 行间 2px | 圆角用 `--r-1`，卡内元素不要再大一级 |
| 行文字 | 标签 **11/500 `--faint`**；数字 **13.5/600 `--text`**，右对齐 + `tabular-nums`（等宽，扫描时有列感） | 与 1B.5 的 `--fs-1 / --fs-3` 对应 |

**「待确认」行的强调（这是这一节最重要的裁决）**

- 数字用 **`--accent-text`**（`#FFD87E`，对 panel 13.03:1）+ **6px `--accent` 圆点**（`margin-left: 6px`）。
- **不用底色。** 理由：底色在本语言里表示「选中/正在操作」，而待确认是一个**状态**。用底会和左栏的选中行互相污染。
- **圆点不是唯一通道**：数字变色 + 圆点 + 行可点 + `aria-label="待确认 12，需处理"` 四重冗余，满足 R3。
- 「可能人像」行可点（进筛选）：右侧 12px chevron `--faint`，hover 行底 `--panel-2`。

**为什么用 `--card` + 阴影，而不是 UX 建议的「`--panel` 且不加阴影」**

UX 的倾向符合 R-G3（阴影只给浮起来的东西）。但这里有两个实测约束：

1. **G1 的 `--panel` 对 `--bg` 只有 1.12**。卡内还有 hover 行，hover 用 `--panel-2` 对 `--panel` 只剩 **1.06**——两档叠起来就「糊平」了。改用 `--card #1E1E1E`（对 bg 1.11、对 hover 行 `--panel-2` 1.20），层级才立得住。
2. **G2 的白卡对纸底只有 1.16**，浅色主题本来就要靠阴影给轮廓（1B.4 已写明暖阴影的作用）。

所以定：**`--card` 底 + `--shadow-1`，不加描边**。阴影在这里承担的**不是「浮起」，是「给一个 1.1 级的分档补一条边界」**——这条要在代码注释里写明，否则下一个人会按 R-G3 把它删掉。

**禁止**：卡内加分割线、加 1px 边框、行高 < 36、把三行做成三个 chip。

#### 1B.13.3 两处修订

**(a) 查看器顶胶囊：宽度必须固定。** UX 指出 `max-width: 62%` 会让胶囊宽度随文件名长度变化 → 换图时宽度跳变，这是新的一种抖动。

**(b) 标题栏：5 个菜单成立，宽度重算。**

|---|---|---|
| 左内边距 | 16 | **20** |

#### 1B.13.5 危险色语言（回填 1B.4 · 回应「工程会不会到处用 `--danger-soft`」）

UX 提得对：我一直在口头用「红底是不可逆的专属语言」，但规范里没登记过，工程看到就会自由发挥。现在登记，**三档，没有第四档**。

| 用法 | token | 值 | 实测 |
|---|---|---|---|
| 危险**文字 / 图标 / 进度** | `--danger` | G1 `#F0664E` / G2 `#C0342A` | **5.69** / 5.17 on bg；panel 5.27 |
| 危险**长句文字**（说明、错误文案、淘汰选中） | `--danger-text` | G1 `#F79A86` / G2 `#A62A21` | on `--panel-2` **7.33**；on `--panel-3` **6.60**（G2 5.11）；on bg 8.41 |
| 危险**实底**（唯一允许填红的场景） | **新增 `--danger-fill`** | G1 `#B33A2B` / G2 `#A62A21`，字 `--on-danger #FFFFFF` | 白字 **5.90** / **7.06** |

**为什么必须登记：`--danger` 不能当填充底。** 它是为「前景」调的亮珊瑚，**白字压不住它**——`#FFFFFF` 在上面只有 **3.13:1**，`#F2F2F2` 只有 **2.79:1**，连深字 `#141414` 也才 5.89。工程最可能犯的错，就是拿 `#F0664E` 当 `background` 再配白字，做出一个「看起来很红很危险、实际看不清字」的按钮。要红底就用更深的 `--danger-fill #B33A2B`。

**唯一允许红实底的场景（穷举，不许扩展）**：① 永久删除的最终确认按钮；② 清空回收站。其余「危险但可撤销」的动作（淘汰、移出文件夹、取消星标、撤销入片）**只用 `--danger-text`**。

## 2. 非 accent 的全局材质语言

### 2.1 冷暖裁决：**表面与文字保持 PA2 冷中性，暖只以「光」出现**

裁决表：

| 层 | 值 | 裁决 |
|---|---|---|
| `--text` 匣壁冷白 | `#E8EEF4`（dark）/ `#1A1D23`（light） | **保持不动**。不转暖、不转中性 |
| `--muted` / `--faint` | `#A7B2C2` / `#8590A2` | **保持不动** |
| `--border` / `--border-strong` | `#262B33` / `#343A44` | **保持不动**（保持中性，不掺暖） |
| `--bg` / `--chrome` / `--panel*` | `#14161B` 系 | **保持不动** |
| accent 相关 6 token | 见 1.4 | 唯一的暖 |

**为什么冷白不被暖琥珀「打架」——三条硬理由：**

1. **看片界面必须是中性锚点**。`#E8EEF4` 彩度极低（S 35%／L 93%），它不是「蓝白」，是「冷白」。若把底与文字整体染暖（例如 `#1A1815` / `#F4F1EC`），用户在存照里判断的白平衡会偏冷，切回 Lightroom 又觉得偏黄——**跨软件的白平衡锚点漂移是摄影工具的原罪**，比「配色和不和谐」严重得多。
2. **冷暖同框是器材的物理真实**：阳极氧化黑铝机身（冷）+ 黄铜卡口/钨丝灯（暖）本身就是一台相机。冷暖不是误差，是材料。
3. **成本**：转暖要动 4 族 ≈30 个值 + 全部对比度复核，收益只是「顺眼」。

**但必须加一条边界（否则冷暖真的会打架）：**

- **暖色不得包裹在中性灰描边里**。规则：凡是 accent 底的容器，描边必须用 `--accent-border`（暖），禁止用 `--border`（中性）。灰边裹暖底会显「脏」。
- **暖色填充面积上限**：单元素 ≤120×32px，单屏 <3%（P1′）。
- **light 主题**例外说明：浅色下 `--accent #9C5410` 与 `--text #1A1D23` 都是深色，靠色相而非明度分层，所以 accent 文字**只允许用在 ≥12.5px 的链接/选中文字**，不得用于 10.5px 的微文字。

### 2.2 五条可执行材质规则（含 CSS）

**R-M1 分隔线：1px 实色，只出现在「结构接缝」**
```css
/* 允许：窗口边缘、面板之间、工具栏/标题栏底边、灯箱条底边 */
border-bottom: 1px solid var(--border);        /* 对 bg 仅 1.27:1——它只分区，不划边界 */
/* 禁止：列表项之间画线（用留白）、渐变线、发光线、inset 高光 */
/* 禁止：box-shadow: inset 0 -1px 0 rgba(255,255,255,.08) 这类「玻璃高光」 */
```
保留现有 `.tb-sep { width:1px; height:18px; background:var(--border) }` 为标准分隔符。

**R-M2 卡片：不投影、不位移**
```css
.card-thumb {
  box-shadow: inset 0 0 0 1px var(--border);   /* 替代 --elev-1 外投影 */
  border-radius: var(--radius-panel);
  transition: box-shadow var(--motion);
}
.card-thumb:hover {
  box-shadow: inset 0 0 0 1px var(--border-strong);  /* 只提亮内环 */
  /* 删除：transform: translateY(-2px); box-shadow: var(--elev-2); */
}
```
理由：缩略图墙最怕抖动（hover 抬升会让整屏 200 张图跟着视觉呼吸）；器材不会「浮起来」。`--elev-2` 只留给真正的浮层（菜单、弹窗、toast）。

**R-M3 表面只允许 4 档，禁止组件内自造层级**
```
--bg → --chrome/--panel → --panel-2 → --panel-3
```
禁止在主界面使用 `bg-white/8`、`bg-black/40`、`rgba(255,255,255,.12)` 制造第 5 档（`Lightbox` 内除外，那里有独立 token 集，见 5.3）。现状 `Lightbox.tsx` 有 **10 种 alpha 临时值、31 处引用**——按 5.3 收敛成 5 个 `--lb-*` token。

**R-M4 三态分工：hover 提亮 / 选中描边 / 聚焦外环，三者形态不同**
```css
/* hover：只提亮一档背景，不描边、不改色相 */
.item:hover { background: var(--panel-2); }
/* 透明底图标按钮：hover 用 1px 内环（因为透明底提亮看不见） */
.icon-btn:hover { background: color-mix(in srgb, var(--text) 8%, transparent); }
/* 选中：2px 指示线 / 2px 内环，不用实底反色；并服从 R2 四件套 */
.side-item.active {
  background: var(--accent-soft);
  color: var(--accent-text);
  box-shadow: inset 0 0 0 1px var(--accent-border), inset 2px 0 0 var(--accent);
}
/* 聚焦：外环，outline-offset 不可删（a11y 硬约束） */
:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }
```

**R-M5 数字化：所有「量」等宽 + 固定宽容器**
```css
.num { font-variant-numeric: tabular-nums; font-feature-settings: 'tnum' 1; }
```
凡「张数 / 焦距 / ISO / 快门 / 百分比 / 角度 / 尺寸」必须 `.num` + `min-width`。这条直接治「换图时底条数字跳动」（见 5.5）。

### 2.3 安静度（密度）调整——只动间距，不动字阶

现状基线：侧栏 `.side-item` 32px、`.section-title` 28px + `mt-3`(12px)、侧栏内层 `px-2 py-2`(8px)、图库 `GAP=10 / PAD=14`、工具栏 `px-3 py-2.5`。

**间距标尺（只允许这 5 档）**：`2 / 6 / 12 / 20 / 32`。

## 3. 图标尺度系统（回应「小图标根本看不清」）

### 3.1 诊断（代码实测，不是感觉）

| `size` | 处数 | 主要位置 | 判定 |
|---|---|---|---|
| 10 | **14** | 卡片角标、微状态 | ❌ 装饰可留，命令禁止 |
| 11 | **45** | 工具栏、详情、弹层 | ❌ 全部不合格 |
| 12 | **109** | 工具栏（`Toolbar.tsx` 24 处）、侧栏、菜单 | ❌ 全部不合格 |
| 13 | 54 | 查看器底条 | ❌ 24px 热区里装 13px 图标（≈54% 占比） |
| 14 | 31 | 部分按钮 | ⚠️ 勉强合格 |
| 15 | 36 | 查看器顶条 | ✅ |
| 16 | 7 | 少量 | ✅ |
| 18 / 20 | 4 / 4 | — | ✅ |

**约 55%（168/304）的图标 ≤12px**，而 Lucide 默认 `strokeWidth=2`——在 12px 网格上，2px 描边占掉 1/6 直径，笔画间隙被填平，这就是「糊成一团」的成因。热区统计：`w-6 h-6`(24px) 6 处、`w-5 h-5`(20px) 2 处，其余小按钮用 `h-5 / h-6 / h-7`。

### 3.2 图标尺寸阶梯（写进 `styles.css` 的 token）

| token | 值 | 允许用途 | 最小热区 | 备注 |
|---|---|---|---|---|
| `--icon-deco` | **12px** | 纯装饰/状态点缀（卡片角标内的勾、色卡、进度点） | — | **不可点击**，不得承载命令 |
| `--icon-inline` | **14px** | 列表行前缀、菜单项、输入框内图标、chip 内图标 | **24×24** | 命令入口的**绝对下限** |
| `--icon-control` | **16px** | 工具栏按钮、`.btn` 内图标、查看器条内图标（默认档） | **28×28** | 绝大多数图标应在此档 |
| `--icon-tool` | **18px** | 主工具栏独立图标按钮、查看器主操作 | **32×32** | — |
| `--icon-hero` | **24px** | 空状态、欢迎页、对话框主操作 | **36×36** | — |

**两条硬线**
- **命令入口图标不得 <14px**（低于此值在多屏 DPI 缩放下必糊）。
- **点击热区不得 <24×24**（WCAG 2.2 SC 2.5.8 Target Size Minimum）。落地值：密集列表/菜单 **24**、工具栏 **28**、查看器 **32**、主操作 **36**。

### 3.3 替换标准（按位置给，不留「自行判断」）

| 位置 | 现状 | 改为 |
|---|---|---|
| `Toolbar.tsx`（24×12px + 4×11px，按钮 `h-8`=32px） | 12/11 | **16px**，热区 32 已达标 → 只换图标，不动按钮 |
| `.btn h-7`（28px）内图标 | 12 | **16px** |
| `.btn h-6`（24px）/ `h-5`（20px）ghost 按钮 | 12 | 图标 **14px**，热区 **升到 24px**（`h-6 w-6` 最小；现在的 `h-5 px-1` 必须改） |
| 菜单项 / 右键菜单 | 12 | **14px**，行高 28px，图标与文字间距 8px |
| `Lightbox` 底条 `w-6 h-6` + 13px | 13 / 24 热区 | **16px / 28×28** |
| `Lightbox` 顶条 `size={15}` + `h-7` | 15 / 28 | **16px / 28**（保持） |
| 卡片角标（`size={10}`） | 10 | **12px**，仅装饰；若是可点击 → 14px + 24 热区 |
| 空状态 / 欢迎页 | 不一 | **24px** 起，插画另算（不受此表约束） |

### 3.4 图标风格裁决（与「器材感」一致）

| 项 | 裁决 | 理由 |
|---|---|---|
| 线性 vs 实心 | **命令入口一律线性**；实心只允许出现在「已激活状态标记」：星标、旗标、勾选、录制点 | 实心是状态，线性是动作——这条把「图标有没有被点亮」变成可读的语义 |
| 描边粗细 | 14–16px → **`strokeWidth={1.75}`**；18–24px → **`strokeWidth={1.5}`**；**禁止默认 2** | 2 在 12px 上糊、在 24px 上「胖」；1.75/1.5 是 Lucide 在暗底上的最佳光学值 |
| 端点/转角 | **圆头（round cap/join）保留** | 1.75px 下方头会产生「缺口」；圆头在暗底上更不易「断笔」。只有刻度线、指示条这类几何元素用直角 |
| 尺寸对齐 | 图标与文本**垂直居中**（`align-items:center`），不参与基线；图标与文字间距 **6px**（按钮内）/ **8px**（菜单） | 避免 12.5px 文字与 16px 图标基线错位 |
| 一套还是多套 | **只用 Lucide 一套**，禁止混入 emoji、彩色图标、第三方图标集 | 混套是「App 感」的最大来源 |

**统一实现**：`<Icon>` 包装组件，默认 `size={16} strokeWidth={1.75}`，禁止各调用点自写数字。

### 3.5 顶部应用图标：**直接删除**（主人明确要求）

现状纠正：窗口顶部那个 16px 小图标**不是自定义标题栏**，是 Electron **原生标题栏**在渲染 `build/icon.png`（`src/main/index.ts:124` 的 `new BrowserWindow`，`title: '存照'`，默认 `frame: true`）。原生标题栏的图标由 DWM 绘制，Electron 没有 API 能单独隐藏——**要「去掉图标」必须换成自定义标题栏**（见第 4 节）。

**去掉图标后品牌感靠什么承载（四层，按重要度）：**

1. **排印**：`存照` 二字，13px / 600 / `letter-spacing: 0.06em` / `--text`。它是窗口内唯一常驻的品牌触点，字距比正文宽 0.06em 就是「铭牌」的全部手法。
2. **留白**：窗口左上角 16px（Windows）/ 78px（macOS）的空白本身就是器材面板的铭牌位。空，是这里的设计。
3. **Logo 只在三处出现**：启动画面、关于页、OS 图标（任务栏/Dock）。
4. **OS 图标的 16px 变体必须换**：任务栏/Alt-Tab 仍会渲染 16px，三张拍立得在这个尺寸不可读。用仓库已有的 `build/icon-mono.png`（单色匣形）作为小尺寸专用资产——这是「小图标看不清」在系统层面的另一半答案。

**明确不做的补偿动作**：不在标题栏画 logo、不画彩色方块、不加「指示灯」小色点（会被误读为状态灯）。品牌感由「字 + 空 + 结构」承担。

## 5. Lightbox chrome 视觉

### 5.1 诊断：为什么会「换图才显示」

`Lightbox.tsx:125-127`
```ts
const idleRaw = useIdle(2000)
const idle = idleRaw && !drawing && !helpOpen
const chrome = `transition-opacity duration-300 ${idle ? 'opacity-0 pointer-events-none' : 'opacity-100'}`
```
根布局是 `flex flex-col`：顶条 `h-[46px] shrink-0` + stage `flex-1` + 底条 `h-[34px] shrink-0`。

**关键事实：两条 chrome 是布局占位的，不是覆盖式的。** `opacity-0` 之后它们**仍然占着 80px**，照片一点也没有变大。再看 `useIdle`（`hooks/useIdle.ts`）：每一次 `pointermove` / `pointerdown` / `keydown` 都调 `wake()` → `setIdle(false)` 并重启 2s 计时器。所以现在的自动隐藏：

1. **不产生任何收益**（条始终占位，淡出后画面一像素都没变大）；
2. **只产生闪烁**：鼠标每移动一次就 `opacity 1`（300ms 淡入）→ 停 2s → `opacity 0`（300ms 淡出）；而**按 ← → 换图本身就是一个 keydown**，也会触发 `wake()` → 于是每翻一页都必然经历「淡入 300ms + 2 秒后再淡出 300ms」；
3. 左右箭头还额外做了一次 `opacity-15` 的「半消失」，在一个已经很弱的状态上再叠一层不确定性。

这是**纯粹的负收益动画**，删掉即可解决主人抱怨的主因。

### 5.2 裁决：**常驻极简 + 显式沉浸**（不推荐继续智能隐藏）

| 方案 | 裁决 | 理由 |
|---|---|---|
| 常驻极简 | ✅ **默认** | 无闪烁、无状态机、照片尺寸不变、信息随时可读 |
| 显式沉浸（用户主动，`Tab` 键 + 底条一个按钮） | ✅ 保留 | 「看纯图」的需求真实存在，但必须是**用户按的**，不是系统猜的 |
| 自动隐藏（idle 2s） | ❌ 普通浏览下废除 | 见 5.1，负收益 |
| 自动隐藏 | ⚠️ **仅幻灯片模式下保留**（见 5.4） | 幻灯片时用户确实「不在操作」，且此时隐藏才真的有意义 |

**裁决一句话**：普通浏览永远常驻；只有幻灯片和用户主动按 `Tab` 时才没有 chrome。

### 5.3 常驻版视觉规格

**结构**：顶条 **40px** + stage `flex-1` + 底条 **36px**（合计 76px，比现在 80px 更省，且不再抖动）。

**新 token（灯箱恒定近黑，与主题深浅无关，因此不吃 `--bg` 系）：**

| token | 值 | 说明 |
|---|---|---|
| `--lb-chrome` | `#0A0C10` | 顶/底条底色（与 `--stage #0C0E12` 差 1 档，形成「条 vs 画面」的软分层） |
| `--lb-rule` | `rgba(255,255,255,0.12)` | 条与画面之间的 1px 分隔（对近黑 1.34:1，只分区不划界） |
| `--lb-text` | `#E8EEF4` | 主文字（16.75:1 on 近黑 ✅） |
| `--lb-faint` | `#8590A2` | 次要文字（6.07:1 ✅） |
| `--lb-hover` | `rgba(255,255,255,0.10)` | 图标按钮 hover 底 |

现状实测：`Lightbox.tsx` 里有 **10 种 alpha 临时值、31 处引用**（`white/8` ×3、`white/10` ×2、`white/12` ×10、`white/16` ×2、`text-white/50`、`text-white/70` ×7、`text-white/80` ×4、`text-white/85`、`border-white/80`、`bg-black/70`），**全部收敛到上表 5 个 token**。

**顶条（40px，`padding: 0 12px 0 16px`；Windows 下右内边距改 **148px**，为原生三键让出 140×36px 禁区，macOS 保持 12px）**
- 左：文件名 `12.5px / --lb-text`，最大宽 **42%**，单行省略；后 `8px`；张数 `6 / 200` `12px / --lb-faint / tabular-nums / min-width 62px`。
- 右：三个按钮，间距 `4px`：

**左右翻页箭头**：**不再淡出到 15%**。规格：`36×36` 圆形按钮，图标 20px；静止态 `opacity: 0.35`、无底；鼠标进入 stage 后 `opacity: 1` + `--lb-hover` 底（60ms 过渡）。原因：淡到 0 会让用户找不到入口，而「找它才出现」正是闪烁感的来源；淡到 0.35 则始终「在那儿，只是不抢」。

### 5.4 唯一允许的自动隐藏：幻灯片模式

```
触发：slideshow === true && 3s 无键盘/指针/滚轮事件 && !drawing && !helpOpen
显示：任何一次键/指针/滚轮 → 立即显示（0ms，无淡入延迟）
换图：不重置计时器，也不触发显示（幻灯片自己翻页不算「用户操作」）
过渡：隐藏 opacity 0 / 60ms；显示 opacity 1 / 0ms
```
**为什么这样不再闪**：① 普通浏览下根本没有 opacity 过渡；② 幻灯片隐藏后用户不动鼠标就不会被「换图」唤醒（因为换图不是用户操作，不重置任何状态）；③ 隐藏/显示都极短（60ms/0ms），不构成「动画事件」。

### 5.5 换图不抖动清单（必做，逐条可测）

1. 文件名容器 `min-width: 0` + `truncate`，`max-width: 42%`（长短文件名不推挤右侧按钮）。
2. 张数 `min-width: 62px`（`9 / 9` → `100 / 12000` 都不跳）。
3. 百分比 `min-width: 46px`、角度 `min-width: 34px`、间隔 `40px`——全部 `tabular-nums`。
4. `useEffect [item?.id]` 只重置**图片状态**（zoom/pan/rotation/region/hint），**不触碰 chrome 可见性**（现在 idle 与之耦合）。
5. L1 曝光三角三组固定宽，缺参数时**保留空位**（不塌陷），否则 a 组会横向滑动。
6. 切换图片时不播放条的任何过渡（`transition: none` 于 `[data-navigating]` 期间）。

## 附录 B｜给 UX 与工程的一句话交接

**给 UX（Phase 2）**：这一轮视觉只解决了「调性、图标、窗口外壳、查看器 chrome 抖动」四件事——accent 从蓝换成暗房琥珀（`#E0883C` / `#9C5410`），意味着**界面上任何一处彩色现在都只有一个解释：灯亮了**，凡是「用颜色表达状态」的地方（选中、进行中、警告、星标、删除）请按附录 A.5 的表逐项归位，别再新增第六种颜色用法；图标从「12px 起」改成「14px 起，热区 24 起」，凡是靠小图标省空间的地方（工具栏 24 个、侧栏、底条）都需要重新排一遍；标题栏从系统原生改为自定义 36px 后，多出来的那一条横向空间是给 Windows 的 `文件/编辑/视图` 用的，**不要把它做成品牌展示位**。

**给工程（Phase 3）**：按附录 A 逐值落 `styles.css` 与 `skins.ts`，`--warn` 三个 token 直接指向 accent 族（不要保留旧琥珀值，否则琥珀与它 ΔE 只有 18.8 会互相吃信号）；`Lightbox` 删掉 `idle` 对 `chrome` 的驱动，改成 40px + 36px 常驻（条本来就占位，淡出没有收益、只有闪烁），EXIF 按 L1/L2/L3 三级重排，并把 10 种 alpha 临时值（31 处）收敛到 `--lb-*` 五个 token；标题栏要走 `titleBarStyle: 'hidden'` + `titleBarOverlay`（Windows 原生标题栏的图标无法单独隐藏），并给查看器右上角留出 140×36px 禁区，因为原生三键绘制在网页之上。
