## 二、不达标项修订建议

### 2.1 dark `--faint` on `--accent-soft`（4.49 ❌）

**修订方式：用法规则，不改色值。**

理由：差异仅 0.01，改 `--faint`（提亮）会连带拉平它与 `--muted` 的层级；改 `--accent-soft`（加深，如 #1A283A 可达 4.62）会**反向加剧**「选中底与 panel 明度差过小」的问题（见审查第 3 条：加深候选使亮度比从 1.127 降至 1.095）。

**修订规则（写入第五节天蓝行）：** `--accent-soft` 表面上的第三级文字一律用 `--muted`（实测 6.75 ✅）或 `--accent-text`（8.49 ✅），禁止 `--faint`。实际场景（选中行的次要信息）用 `--muted` 语义也更正确——选中行整体已被强调，其中没有「最弱」文字的位置。

### 2.2 light `--star`（3 处 ❌：panel-3 2.81 / accent-soft 2.89 / danger-soft 2.94）

**修订色值：`--star` light 值 `#B88010` → `#A0720E`。**

修订后实测（目标 ≥3:1，全背景）：

| 背景 | #B88010（原） | #A0720E（修订） |
|---|---|---|
| --bg #F0F3F7 | 3.08 | 3.84 |
| --panel #FFFFFF | 3.42 | 4.28 |
| --panel-2 #F4F7FA | 3.18 | 3.98 |
| --panel-3 #E4E9F0 | 2.81 ❌ | 3.51 |
| --canvas #F7FAFC | 3.27 | 4.36（注：canvas 上原值 3.27，修订 4.36） |
| --accent-soft #E3EDF9 | 2.89 ❌ | 3.62 |
| --danger-soft #FBEAE7 | 2.94 ❌ | 3.67 |

修订后最低 3.51（panel-3），全部背景留有 ≥0.5 余量；与 `--accent` #2F6CB8 的 ΔE76 = 101，图形色之间无混淆风险。`#A0720E` 仍在暖黄同色相的加深方向上，符合 P3（不引入新色相）。

**代价与对策：** 修订后 light star 与 `--warn` #8A5B14 的 ΔE76 从 21.7 收窄到 13.5。二者本就靠形态区分（实心五角星 icon vs 警告正文/三角形 icon），且第五节已把两者场景封闭、禁止同用，可接受。但需把「星标与警告不得仅靠颜色区分、必须字形不同」写为硬约束（见审查第 2 条）。

### 2.3 修订 token 汇总（仅 1 个色值 + 3 条规则，零新增变量）

| 类型 | 内容 |
|---|---|
| 色值 | light `--star`：`#B88010` → `#A0720E`（第三节表内单格替换） |
| 规则 R1 | dark `--accent-soft` 表面禁用 `--faint` 文字，用 `--muted`/`--accent-text` |
| 规则 R2 | 选中态必须「四件套」：`--accent-soft` 底 + `--accent-border` 边 + `--accent-text` 字 + ≤2px `--accent` 指示条，禁止只用 soft 底（描边对 panel 仅 1.56–1.62:1，明度差见审查第 3 条） |
| 规则 R3 | 红/绿/黄等状态语义禁止只用颜色承载：状态点必须配 icon 字形或文字（WCAG 1.4.1） |

## 三、可用性审查结论（逐条）

### 3.1 天蓝 accent 四职（选中 + 链接 + 进度 + focus）是否语义过载

**结论：可接受，附 1 个条件。**

四职统一在「系统回应你」单一语义下（P2），符合 Nielsen 一致性启发式；且每个角色都有**非颜色形态冗余**，不依赖色彩单独区分：
- 选中：soft 底 + 描边 + 左侧指示条（区域形态）
- focus：`outline 2px + offset 2px`（外环，与选中描边内外分层，键盘导航已选中行时双层可辨）
- 链接：行内文字形态（vs 块状选中）
- 进度：连续动画 + 长度变化

**条件**：focus 环使用 `--accent`（dark 5.88:1 on panel ✅ 图形级达标），键盘用户在蓝色选中行上再获得蓝色外环时靠 offset 分层——Phase 3 不得移除 `outline-offset`；进度条应带百分比/文字冗余，动画丢失（prefers-reduced-motion）时仍有长度信息。

### 3.2 星标（--star）与警告（--warn）在色觉障碍/小尺寸下的可分性

**实测：**

| 主题 | ΔE76 | 相对亮度差（0–100） | 二色对比 | Deuteranopia 模拟后 ΔE / 亮度差 |
|---|---|---|---|---|
| dark #F5C344 vs #D9A54A | 17.9 | 16.7 | 1.35:1 | 16.1 / 18.6 |
| light #B88010 vs #8A5B14 | 21.7 | 12.7 | 1.71:1 | 22.9 / 17.7 |

**结论：仅靠颜色不可靠区分（ΔE < 25 且对比 < 3:1，deuter 模拟下两色趋同为黄系，只剩明度差约 13–19 撑着）。但规范的形式设计已兜底**：P2 把两色场景封闭（星标只出现在评分行/旗标 icon，警告只出现在消息文字），禁止同用、禁互借用；两者字形必然不同（实心五角星 vs 警示三角/正文）。**满足 WCAG 1.4.1**。需把 R3 落为硬约束：任何场景禁止把「星标填充 vs 警告文字」做成同字形不同色的两个元素。light star 修订为 #A0720E 后与 warn 的 ΔE 降至 13.5，此约束的重要性上升，但形态差异（icon vs text）仍足够。

### 3.3 dark 选中底 `--accent-soft` 与 `--panel` 的状态可区分性

**实测：ΔE76 = 10.4，相对亮度差 0.82（亮度对比 1.127:1）。**

明度差极小，区分几乎完全靠色相偏移——余光扫视、低质量屏、色弱用户下，**只涂 soft 底的选中态有一眼漏掉的风险**（这正是规范第九节 4 规定四件套的原因）。附测：单用 `--accent-border` 也不够（1.62:1）。**判定：按四件套组合执行则可区分性成立**（accent-text 文字 10.6:1 级别变化 + 指示条 6.5:1 都是强信号），但必须把 R2 写为 Phase 3 硬约束：选中态禁止 soft 单独出现。不建议加深 accent-soft 换取明度差——实测加深到 #1A283A 只把亮度比降到 1.095（更接近 panel），且破坏「天蓝 12% 叠加」出处。

### 3.4 红（danger）绿（success）在 Deuteranopia 下的依赖

**实测（Viénot 模拟）：**

| 主题 | 模拟后 danger / success | ΔE76 | 亮度差 | 对比 |
|---|---|---|---|---|
| dark | #CBD44A / #9A9494 | 70.5 | 30.1 | 1.86:1 |
| light | #A6AE2A / #57514F | 71.6 | 30.1 | 3.23:1 |

模拟下二者仍可分（主要靠约 30 的明度差），但 dark 侧对比仅 1.86:1——若做成同样式的小色点，色觉障碍用户分辨不保证。**规范现状**：success 只用于「已保存/已导出/完成」消息、danger 只用于破坏性确认弹层，二者场景封闭、且均伴随文字（「已导出」vs「永久删除」）→ 1.4.1 形式满足。**缺口**：规范没有明文要求「状态不得只用色点承载」。以 R3 补上：成功/错误 toast、同步状态点等，必须 icon（✓/⚠）或文字随行，禁止裸色点。

### 3.5 light 灯箱仍用近黑（rgba(10,12,16,0.97)）的合理性

**确认合理，维持。** 理由：1) 看大图时近黑衬底是摄影语境的显示功能需求（读影调需要最低环境干扰），与主题深浅无关——spec 第七节已论证（印刷匣 vs 屏幕媒介的差异）；2) 控制条文字实测：#E8EEF4 on 近黑 = 16.75:1，#A7B2C2 = 9.12:1，浅色主题下灯箱内文字反而比深色主题更无风险；3) 0.97 不透明度下背景透色对衬底色温的影响 <1%，稳定。唯一提醒：浅色用户从白界面进入近黑灯箱是**大的亮度跳变**，建议灯箱打开动效用 spec 既有 `--motion`（150ms）渐入，避免瞬闪（此为已有行为校准，非新增需求）。

### 3.6 主按钮禁用态可读性

dark 4.22:1 / light 4.92:1（faint on panel-3）。禁用态 WCAG 不强制，但「可读且明显弱于可用态」是好的防误设计（Nielsen 防错启发式）：dark 4.22 高于 3:1 可辨认、低于 muted 正常态形成层级；light 4.92 几乎是正文级。**判定：放行，原样执行。** 附小建议（可选，非阻塞）：dark 禁用态若想再拉开层级，可加 `opacity` 不必要——保持现状即可，勿用 0.4 类低透明度把对比度打穿 3:1。

### 按本报告修订执行（1 色值 + 3 规则）

1. **light `--star`：`#B88010` → `#A0720E`**（第三节表内单格替换；SKINS 中 paper 的 swatches 不含 star，无需同步）。落点：`styles.css` 的 `:root[data-theme='light']` 与 `:root[data-skin='paper']` 两段（若 paper 段为整表复制则同步替换）。
2. **R1**：dark `--accent-soft` 表面文字层级最低到 `--muted`，禁用 `--faint`（修订 dark `--faint` on accent-soft 4.49 → 6.75）。落点：选中行/选中卡片组件的次要文字。
3. **R2**：选中态强制四件套（soft 底 + border 边 + accent-text 字 + ≤2px accent 指示条），禁止 soft 单独出现（accent-border 单独对 panel 仅 1.56–1.62:1）。落点：所有 `.selected/.active` 类组件。
4. **R3**：状态语义（成功/失败/警告/标记）必须 icon 或文字冗余，禁止裸色点、禁止同字形仅异色。落点：toast、同步状态、评分行。

### 数值速查（Phase 3 自检用最低安全线）

- dark 正文最低安全组合：`--faint` on `--panel-2` = 4.71（全表最低的正文级组合，勿再叠透明度）。
- light 图形最低安全组合：`--star` #A0720E on `--panel-3` = 3.51。
- contrast skin 最低：`--faint` on `--accent-soft` = 7.28。

## 附：复核方法与脚本

- WCAG 2.1 对比度：标准相对亮度公式（sRGB → 线性化 → 0.2126/0.7152/0.0722 加权）。
- 色差：CIE Lab (D65) ΔE76。
- 二色觉模拟：Viénot 1999 线性 RGB 投影法（deuteranopia 近似）。
- 脚本：`%TEMP%\lunaris_contrast_check.py`（临时文件，一次性，不入库）。全部 105 项组合 + 语义区分度 + 修订候选均可复算。
