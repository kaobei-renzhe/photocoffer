# 主题色与深浅色适配 · 优化方案

> 实测方法：解析 `styles.css` 里 7 套配色的全部颜色变量，按 WCAG 公式算关键组合的对比度。
> 结论：**需要优化，但只改 CSS 变量，一行组件代码都不用动。**
> 三个问题，其中一个是全线性的。

---

## 0. 一句话结论

**`--faint` 在 7 套主题里全部不达标**（2.58–3.95，标准 4.5）。

而这个变量承载的是「提示文字、数字、占位符」——**恰恰是用户必须读到的辅助信息**。它太淡，等于这一层信息对用户不存在。

我之前说"灰度只有两层"，准确的描述是：**有三层，但第三层等于看不见。**

## 3. 施工方法

**全部在 `src/renderer/src/styles.css` 里改变量值，不碰任何组件。**

分三步，每步都能单独看效果：

1. **只改 `--faint`**（7 处）→ 立刻能感觉到"小字看得清了"
2. **只改 `--bg` / `--panel`**（7 处）→ 侧栏和主区终于分得开
3. **只改 `--star`**（3 处）→ 浅色下星星能看清了

**别一次全改**，否则视觉变化太大反而判断不出哪步有效。

---

## 4. 验收

- [ ] 7 套主题下，`--faint` 的对比度都 ≥ 4.5
- [ ] 每套主题的 `bg/panel` 差异 ≥ 1.10
- [ ] 浅色系星标 ≥ 3.0
- [ ] 切换深浅色时，**没有任何一处文字变得看不清**
- [ ] 侧栏和主区能一眼分出边界（不用眯眼）

最后一条是最直观的：**眯起眼睛看，侧栏应该是一块能辨认的色块，而不是和主区融成一片。**

## 5. 一个可以留着的自检脚本

以后加新皮肤、改配色，跑一下就知道有没有翻车。

放到 `scripts/check-contrast.mjs`：

```js
import { readFileSync } from 'node:fs'

const css = readFileSync('src/renderer/src/styles.css', 'utf8')
const lum = (h) => {
  const [r, g, b] = [1, 3, 5].map((i) => parseInt(h.slice(i, i + 2), 16) / 255)
  const f = (c) => (c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4)
  return 0.2126 * f(r) + 0.7152 * f(g) + 0.0722 * f(b)
}
const ratio = (a, b) => {
  const [x, y] = [lum(a), lum(b)].sort((m, n) => n - m)
  return (x + 0.05) / (y + 0.05)
}

const blocks = {}
for (const m of css.matchAll(/(:root(?:\[[^\]]+\])?[^{]*)\{([^}]*)\}/g)) {
  const vars = Object.fromEntries([...m[2].matchAll(/--([\w-]+):\s*(#[0-9a-fA-F]{6})/g)].map((v) => [v[1], v[2]]))
  if (!vars.bg) continue
  const key = m[1].replace(':root', '').replace(/\[|\]|'|"|data-theme=|data-skin=/g, '') || 'dark'
  blocks[key] = vars
}

let bad = 0
for (const [name, v] of Object.entries(blocks)) {
  const checks = [
    ['text/bg', v.text, v.bg, 4.5],
    ['faint/panel', v.faint, v.panel, 4.5],
    ['muted/panel', v.muted, v.panel, 4.5],
    ['bg/panel 层次', v.bg, v.panel, 1.1],
    ['star/panel', v.star, v.panel, 3.0]
  ]
  for (const [label, a, b, need] of checks) {
    if (!a || !b) continue
    const r = ratio(a, b)
    if (r < need) {
      bad++
      console.log(`✗ ${name.padEnd(10)} ${label.padEnd(14)} ${r.toFixed(2)} < ${need}`)
    }
  }
}
console.log(bad ? `\n${bad} 处不达标` : '\n全部达标 ✓')
```

在 `package.json` 加一行 `"check:contrast": "node scripts/check-contrast.mjs"`，以后 `npm run check:contrast` 就能查。

## 6. 一个判断

主人这套配色系统本身做得挺讲究：**7 套皮肤、254 处变量引用、深浅两套都有完整定义**。这不是随手写的。

问题不在设计能力，在于**没有量化标准**——凭感觉调色，很容易在某一层"再淡一点更好看"，然后淡过头。

对比度就是那个量化标准。它不限制审美，只是保证**下限**：颜色你怎么调都行，但别低过这条线，否则用户就读不到了。

---

## 明确不做的

| 别做 | 原因 |
| --- | --- |
| 顺手改组件代码 | 只改 `styles.css` 里的变量值。一旦开始动组件，就分不清是哪一步生效了 |
| 改 `--accent` 的色值 | 问题是它出现得太多，不是选得不好。换色会让所有 accent 位置一起变 |
| 为了"好看"临时压低对比度 | 4.5 是**下限**不是目标。可以往上调，不能往下抹 |
| 一次改完 7 套再一起看 | 一套一套改、一套一套看。7 套同时改出错很难定位 |
| 只改 `--faint` 就去调布局 | 表面层次没拉开之前调布局，判断会失真 |
| 顺便新增灰度变量 | 现有三层够用，新增一层要重判 254 处引用 |
