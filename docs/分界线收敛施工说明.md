# 分界线收敛 · 施工说明

> 触发：主人反馈「左右分界线有两条感觉有点奇怪；上面的分界面缺少了一部分」。
> 产出方：UI 设计全栈专家团（视觉方向 → 体验规范 → 前端落地，主理人汇编）。
> 目标：每边界只留一条线；顶部横线全宽连续；竖线与横线 T 字相接。
> **只给方案，代码在 Trae 里改。** 所有行号 / 变量名均已对照 v0.4.1 实测。

---

## 0. 两个缺陷的根因（已核实）

### 缺陷一：左右各出现两条竖线

每个边界被**两个元素各画了一条线**：

| 边界 | 第一条 | 第二条 |
| --- | --- | --- |
| 左侧栏右缘 | `Sidebar.tsx:800` 的 `border-r border-[var(--border)]` | `ResizeHandle.tsx:63` 内居中 `w-px` span |
| 右侧栏左缘 | `ResizeHandle.tsx:63` 的 span | `DetailPanel.tsx:59` 的 `border-l border-[var(--border)]` |

两条低对比线（`--border #E6DCCB`，对白约 1.3:1）中间夹着 6px 手柄的透明空隙，露出比两侧 `--chrome #FFFDF9` 更暖更暗的 `--bg #FAF6EE` —— 读成「凹槽 / 双描边」，浅暖调下认不出哪条是真边界。hover 时 span 变 2px 亮黄、旁边还留一条米线，更脏。

**结论：只留一条，由 `ResizeHandle` 的 span 承担，删掉两栏的 border。**
理由：① hover / 拖拽高亮只能挂在手柄上，且与 6px 命中区同位；② 分界是「两栏之间的关系」，栏隐藏时手柄随之消失，不留孤线；③ 单一来源，避免两条线在不同皮肤下漂移。

### 缺陷二：顶部横线在右侧缺一段（判定为遮断，不是没对齐）

`TitleBar.tsx:77` 的 `border-b` 横线进入右上角约 148px 的 **Windows 原生三键 overlay 区后被 OS 原生层遮掉**（`src/main/index.ts:136` 的 `titleBarOverlay{ height: 36 }`）。`TitleBar.tsx` 末尾的 `w-[148px]` 只是透明占位，不补线。

不是「竖线顶端没对齐」——放大图里竖线顶端正好落在横线上，是干净的 T 接。

**结论：横线改由三栏容器的顶边承担**（该容器从 y=36 起，在 overlay 覆盖区之下，能全宽连续），TitleBar 去掉 `border-b`。148px 禁区保持 `--chrome` 透明、不画线、不放可点元素。

## 2. 顶边线为什么用 `border-t` 而不是 `border-b` / inset shadow

**结论：用 #1 + #2 组合（容器 `border-t` + 同步删 TitleBar 的 `border-b`），不用 `box-shadow: inset`。**

- `* { box-sizing: border-box }` + `h-9`=36px：TitleBar 的 `border-b` 占 y=35–36，容器的 `border-t` 占 y=36–37。**不是同像素叠加，但同色相邻会连成 2px 粗线**，所以 #1 #2 必须同批做，不能只做一个。
- 用 `border-t` 会占 1px 布局空间，使 `ResizeHandle` 的 `inset-y-0` 竖线自 y=37 起，与横线干净 T 接、不重叠、不穿入标题栏。
- inset shadow 不占布局空间，竖线会从 y=36 起在交点叠粗，且容易被子元素底色 / 亚像素抗锯齿冲淡。
- `border` 不会撑高布局（`flex-1 + min-h-0` 吸收这 1px，无重排）。
- overlay `height: 36` 只遮 y<36，容器线从 y=36 起因此全宽连续（含三键正下方）。

## 3. ResizeHandle 改法（6px 占位不变，命中区扩到 10px）

`:61` 整行替换为：

```jsx
      className="group relative z-10 w-[6px] shrink-0 cursor-col-resize select-none before:absolute before:inset-y-0 before:left-1/2 before:-translate-x-1/2 before:w-[10px] before:content-['']"
```

`:63` 整行替换为：

```jsx
      <span className="pointer-events-none absolute inset-y-0 left-1/2 -translate-x-1/2 w-px bg-[var(--border)] transition-colors group-hover:w-[2px] group-hover:bg-[var(--accent-strong)] group-active:w-[2px] group-active:bg-[var(--accent-strong)]" />
```

说明：
- `before:` 伪元素居中 10px、左右各溢出 2px，`absolute` 不占布局，**可见宽度仍是 6px**；命中仍落在宿主 div，`onPointerDown` / `setPointerCapture` / `onDoubleClick` 全部不变，且继承宿主 `cursor-col-resize`，外扩区也能触发 `group-hover`。
- `group-active` 复用 CSS `:active` 做拖拽态，**零新增 state、零重渲染**。
- hover 用 `--accent-strong`：当前 light/paper 下是 `#A66C00` 暖棕（对 `--chrome #FFFDF9` 约 5:1，达标）；原来用的 `--accent #FFC44D` 亮黄只有约 1.6:1，几乎看不见。night/contrast 皮肤下 `--accent-strong` 自动是亮黄，同样达标。**这个变量真实存在**（`styles.css:33/130/191/249/307`）。
- 粗细瞬时变化 + 颜色过渡满足「不只靠颜色表状态」；`reduced-motion` 已由 `styles.css:639-647` 全局 `transition-duration:.01ms` 覆盖，无需另改。

## 4. 去掉重复横线（Phase 2 体验规范配套）

实测三条内容条带都自带 `border-b`，与新的顶边线会形成表格感：

| 位置 | 现状 | 改法 |
| --- | --- | --- |
| `App.tsx:1767` 离线警告条 | `border-b border-[var(--warn-border)]` | 删横线，保留 `bg-[var(--warn-soft)]` 底色块 |
| `App.tsx:1828` 相似图条 | `border-b border-[var(--border)]` | 删横线，保留 `bg-[var(--panel-2)]` 底色块 |
| `Toolbar.tsx:218` | `border-b border-[var(--border)] bg-[var(--chrome)]` | 删横线，底色 `bg-[var(--chrome)]` → `bg-[var(--panel)]` |

> `Gallery.tsx` 无背景、继承 `--bg`，所以 Toolbar 换成 `--panel` 后底色能拉开层次，不需要描边。
> 离线条与顶边线实测只隔约 34px，违反「40px 内不并置两条横线」的硬规则，必须改。

定性：顶边线是**唯一全宽框架边界**；其下条带都是内容内分隔，用底色 / 间距区分，多条同现时只留最下一条。

## 5. 验收清单

1. `npm run typecheck`（= `tsc --noEmit`）0 error，再起窗口。
2. DevTools 计算样式核对：
   - `Sidebar` / `DetailPanel` 根元素 `border-width: 0`
   - 三栏容器 `border-top-width: 1px`
   - `TitleBar` `border-bottom-width: 0`
   - 两处 handle 各只有 1 个 `w-px` span
3. 肉眼：y=36 横线**从最左连到最右**，右上 148px 三键区正下方也有线、无断口；T 接处竖线自横线下方起，不重叠不加粗。
4. **眯眼法**：窗口缩到 50% 或后退半米眯眼看 —— 左右各应只有 1 条细线。若见两条、或一条发灰加粗，说明漏删了栏 border 或 TitleBar 的 `border-b` 还在。
5. 交互：线左右各 5px 仍是 `col-resize` 且 hover 变 2px 深棕；拖拽保持 2px；双击复位宽度；关闭右栏时右线整条消失（不留孤线）；离线条出现时顶部 40px 内只有 1 条横线。
6. 切到 night / paper / contrast 皮肤和 reduced-motion 各看一眼，确认 hover 色达标、过渡不闪。

## 6. 明确不做（防止 Trae 自作主张）

| 别做 | 原因 |
| --- | --- |
| 不重构三栏 flex 结构 | 本次只改 class，不动 DOM 层级 |
| 不把右栏 `ResizeHandle` 移出 `{activeItem && ...}` 条件 | 现状已合规：`App.tsx:1875` 与 `:1887` 同一条件，同帧生灭，全程 0 或 1 条线 |
| 不改 `src/main/index.ts:136` 的 `titleBarOverlay` 高度 / 颜色 | 动了会连带影响三键区与 mac 红绿灯死区 |
| 不动 `TitleBar.tsx` 末尾 `w-[148px]` 禁区 | 保持透明、不画线、不放可点元素 |
| 不给 `role="separator"` 加 `tabIndex` / 方向键调宽 / `aria-valuenow` | 面板宽度不是核心任务，新增 Tab 停靠点反而打断浏览；保留不可聚焦的静态 separator + 双击复位 |
| 不删 ResizeHandle、不用 CSS `resize` 替代 | 拖拽逻辑、记忆宽度、双击复位都在里面 |
| 不给 Sidebar / DetailPanel 补任何替代 border | 会重新变成两条线 |
| 不改 `styles.css` 变量表 | 现有变量够用；hover 复用 `--accent-strong` 即可 |
| 不做「首次使用拖拽提示」 | 可选增强，本次不引入持久化状态 |
| 不动 `DetailPanel.tsx:62/72` 与 Toolbar 内部的局部 border | 那些是内部区块分隔，不是三栏边界 |

## 7. 一句话验收

> 顶部一条 1px 横线从最左连到最右（含三键下方），其下左右各仅一条 1px 竖线与之 T 字相接；悬停变 2px 暖棕、移开复原，全屏看不到双线，也看不到横线断口。
