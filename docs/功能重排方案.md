# 功能重排方案

> 触发问题：APP 做到了「最小体验满足」和「最大功能选择」吗？
> 答案：最小体验约 70%（前六步顺，第七步"用上"断了），最大功能约 120%（过剩）。
> **不是功能多少的问题，是一条流程被切成了几段，散在不同地方。**
>
> §1–§6 按「商业摄影用户」重排入口；**§7 补上另一半用户**——只做图片管理、不接单的人（很可能是多数），以及两类用户怎么共用一套界面。

---

## 0. 先说现状：哪些已经做得很好了

重排不是推翻重来，先把已经对的确认下来：

| 已经做好的 | 说明 |
| --- | --- |
| 空库引导 | 「图库还是空的」+ 拖拽提示 + 导入按钮，写得挺好 |
| 筛选排可折叠 | `filtersOpen` 状态已经有了，默认收起 |
| 选中操作条 | 选中照片后出现 accent 色条，做/出操作都在里面 |
| 搜索模式切换 | 语义 ↔ 普通，placeholder 跟着变，设计得好 |
| 语义搜索入口 | 紧贴搜索框，符合"它是搜索的一种模式" |

**这些不用动。**

## 1. 真正的问题：「选片交付」散成了四段

这条流程本该是连贯的，现在被拆到三个地方：

| 动作 | 现在在哪 | 用户什么时候能找到 |
| --- | --- | --- |
| 生成选片页 | 选中照片后的操作条 | 得先选中一批 |
| 导入客户结果 | 工具栏第一行右侧 | 藏在搜索框旁边 |
| 选片记录 | 侧栏 | 要自己点进去 |
| 导出成品 | 侧栏 | 同上 |

**一条流水线，四个入口，三个地方。** 用户脑子里是"我要把这一单交出去"，但他得记住四个位置。

---

## 2. 核心改动：做成「选片交付」工作区

参照已有的「人像工作台」（这个思路是对的，继续用）。

### 2.1 视图内容

```
选片交付
├── 待交付          选好一批照片、还没发出去的
├── 已发出          等客户回复的（显示发了几天）
└── 已完成          客户选完、已经出片的
```

点进一单，看到的是这条线：

```
[这批 128 张] → [生成选片页] → 已发给客户（3 天前）
                                    ↓
                              [粘贴客户回复]
                                    ↓
                          客户要 18 张 · 要修 3 张
                                    ↓
                              [导出成品]
```

**一条线在一屏里看完**，不用记四个入口。

### 2.2 入口

侧栏导航第三个从「选片记录」改成「选片交付」，点进去就是这个视图。

原来的「选片记录」弹窗（`PickHistoryDialog`）内容并进来，不再单独弹。

### 2.3 其他三个入口的处理

| 原入口 | 处理 |
| --- | --- |
| 工具栏「导入选片结果」 | **移除**，进工作区的「粘贴客户回复」 |
| 选中操作条的「生成选片页」 | **保留**——选中就能发，这个操作流是对的 |
| 侧栏「导出成品」 | **移进工作区**，只在"已完成"的单里出现 |

> 保留操作条那个入口很重要：选中一批 → 直接生成，是最顺的一条路。工作区是"管理已发的单"的地方，不是唯一入口。

## 3. 顺带收拾两处

### 3.1 工具栏第一行：7 → 4

现在：`搜索` `语义` `筛选` `最新导入` `导入选片结果` `30409 张` `缩略图滑块`

去掉「导入选片结果」后还剩 6 个。再把**缩略图滑块收进「视图」菜单**（它不是高频操作，占着一整段横向空间）。

最终：

```
[搜索..................] [筛选 ③] [最新导入 ▾] [⊞] ......... [30,409 张]
```

`⊞` 是视图菜单，里面放：缩略图大小、排列方式、展开连拍。

### 3.2 侧栏：四段叠 → 三段分开

```
[月相]                    [↔ 切换图库]
────────────────────
全部图片        30,409      ← 导航
人像工作台
选片交付                    ← 改名后
────────────────────
源目录            1         ← 库内容（可折叠）
文件夹            0
标签             23
智能文件夹        2
────────────────────
装备 · 维护 · 导出成品        ← 工具（收进一行）
────────────────────
[导入图片]  [⋯]
```

**改动点：**
- 「选片记录」→「选片交付」，从弹窗变视图
- 「装备」「维护」「导出成品」三个独立项收成一行文字入口，或者进 `⋯`
- 底部 5 个按钮 → 主按钮 + `⋯`

## 4. 新手路径：一句提示，不是教程

### 时机

只在**首次导入完成**时触发一次，`localStorage` 记住。

### 形态

不用弹窗，用**底部一条不打扰的提示**，3 秒后自动淡出，可点击：

```
┌───────────────────────────────────────────────┐
│ 导进来了 128 张。要不要顺手打个标签，或者…      │
│                          [打标签]  [发给客户]  │
└───────────────────────────────────────────────┘
```

点「发给客户」直接把用户带到选片交付流程——**这是新手最该知道、但最难自己发现的那件事**。

### 为什么不用教程弹窗

弹窗会被立刻关掉，而且一次说完所有功能等于什么都没说。**在他刚完成一件事的时候，告诉他下一步能做什么**，才有人看。

## 5. 施工顺序

| # | 做什么 | 依赖 | 验证 |
| --- | --- | --- | --- |
| 1 | 侧栏「选片记录」→「选片交付」，并把 `PickHistoryDialog` 内容搬进独立视图 | 无 | 点进去能看到三组状态 |
| 2 | 工作区里加「生成选片页 / 粘贴回复 / 导出成品」三个动作 | 1 | 一条线在一屏走完 |
| 3 | 工具栏移除「导入选片结果」，缩略图收进视图菜单 | 2（先确保新入口能用） | 第一行只剩 4 个控件 |
| 4 | 侧栏三段化，底部按钮收进 `⋯` | 无 | 侧栏一眼能分三段 |
| 5 | 首次导入完成的提示条 | 2（按钮要能跳过去） | 首次导入后出现，点一次不再出现 |

**1 和 2 是核心，3–5 是收尾。** 建议先只做 1–2，跑一单真实客片，再决定要不要动侧栏。

> 面向纯图片管理用户的三件事（首启分岔、Ctrl+V 粘贴入库、文案去「客户」化）在 **§7.5**，可与此并行，其中粘贴入库优先级最高。

## 6. 验收

- [ ] 从"选好片"到"客户选完、导出成品"，全部在一个视图里完成
- [ ] 工具栏第一行 ≤4 个控件
- [ ] 侧栏三个分区不用细看就能分开
- [ ] 首次导入后出现提示条，点"发给客户"能直达选片交付
- [ ] 人像工作台的行为完全没变（那是已经对的东西）
- [ ] 所有原有功能都能找到（只是位置变了，不是删了）
- [ ] **纯管理路径两步闭环**：Ctrl+V 能把截图存进来，Alt 拖拽能把图拖出去
- [ ] 首次启动选「整理自己的照片」后，侧栏不出现人像工作台 / 选片交付
- [ ] 用过一次摄影功能后，它自动常驻侧栏，不用回设置里翻
- [ ] **AI 评分、主色筛选在两种模式下都在**（它们不是摄影专属，别一起收掉）

最后一条是底线：**重排只搬位置，不删功能。**

## 7. 两类用户，两种「最小体验」

前面的重排默认了一个前提：**用这个软件的人是拍片接单的**。但这个前提只对一半人成立，而且很可能是少数。

### 7.1 两条闭环，共用一套底盘

```
                共用底盘（导入 · 缩略图 · 预览 · 搜索 · 标签 · 文件夹）
                 /                                    \
        纯图片管理                                  商业摄影
  导入 → 归整 → 找到 → 拖出去用        导入 → 归组 → 打标 → 选片 → 交付
```

前半程完全一样，**只在「怎么把照片用掉」这一步分岔**。

| 用户 | 「用上照片」是什么意思 | 规模 |
| --- | --- | --- |
| 纯图片管理 | 图已经拖到微信 / PS / 资源管理器里了 | 多数 |
| 商业摄影 | 客户拿到照片了 | 少数，但付费 |

### 7.2 纯图片管理这条路，其实已经走完了

好消息是底盘不缺东西，几个关键出口都已经实现：

| 能力 | 状态 | 位置 |
| --- | --- | --- |
| Alt 拖拽到资源管理器 / PS / 微信 | ✅ 已有 | `Gallery.tsx:326` `window.api.startDrag` |
| Ctrl+C 复制图到剪贴板 | ✅ 已有 | `window.api.copyImage` |
| 拖文件进窗口入库 | ✅ 已有 | 「松手就收进图库」 |
| 搜索 / 语义搜图 / 按主色 / 找相似 | ✅ 已有 | — |
| 树形标签 / 文件夹 / 智能文件夹 | ✅ 已有 | — |

这几点恰恰是同类软件的短板——很多工具只能「导出到某个目录」，拿出去用还得再翻一次文件夹。**这块不用动。**

### 7.3 真正的缺口只有三个

**① 没有分岔口**

25 个工具栏控件 + 1335 行设置面板。一个只管理图片的人一进来，看到「人像工作台」「选片记录」「构图筛选」，心里第一句是"这不是给我用的"，但找不到地方关掉，也不知道**前一半功能本身就已经够用**。

不是功能多的问题，是**没有一句话告诉他「你可以只用前一半」**。

**② 缺一个「存一张图」的入口**

纯管理用户最高频的动作是：**看到一张好图 → 存下来**。现在只有「导入文件夹」和「拖文件进来」两条路。

缺的入口：

| 入口 | 为什么重要 | 实现要点 |
| --- | --- | --- |
| **Ctrl+V 粘贴剪贴板图片入库** | 截图后最顺的路径，现在得先存成文件 | 渲染层 `paste` 事件取 `clipboardData.files`，交给主进程写入图库目录 |
| **拖图片网址进来存图** | 收灵感图的主要来源 | 判断 `text/uri-list` / `text/plain` 是不是图片 URL，下载后存 `source_url` |

> `source_url` 目前**没有**这一列（现有 `sources` 表是文件夹级别的导入源）。要做得加一个 `items.source_url TEXT`，属于纯加列，零迁移风险。

**③ 选片页被「客户」两个字挡在门外**

选片页这个能力对纯管理用户也有用——「给朋友看这几张」。但入口叫「选片记录」、流程叫「客户选片」，这些人根本不会点进去。

**功能一行代码不用改，换文案就多一批用户：**

| 现在 | 建议 |
| --- | --- |
| 选片记录 | 分享 / 选片页 |
| 客户选片页 | 生成浏览页（副标题说明可发给客户） |
| 粘贴客户回复 | 粘贴反馈 |

### 7.4 不做模式开关，做「随使用长出来」

**明确反对「简单模式 / 专业模式」的开关**，三个理由：

1. 一旦切了回不去，用户会怕点（"开了专业模式会不会乱"）
2. **用户会成长**——今天纯管理，半年后可能真接单了，开关却卡在旧状态
3. 「专业模式」这四个字本身就吓人，等于承认默认模式是业余的

改成两件事：

**(a) 首次启动问一句**

不是一个问卷，就一个二选一，随时能改：

```
你主要用月相做什么？
  ○ 整理自己的照片和灵感图
  ○ 拍片接单，要交付给客户
                    （以后随时在设置里改）
```

**(b) 功能随使用长出来**

选「整理」时，把**摄影专属**的收进侧栏一个「更多」组，用过一次就自动常驻。

| 该收起的（摄影专属，5 项） | 不该收的（通用，纯管理也要用） |
| --- | --- |
| 人像工作台 · 选片交付 · XMP 侧车 · 研读 · 9 个维度 | 导入 · 浏览 · 搜索 · 标签 · 文件夹 · **AI 评分** · **主色** · 去重 · 找相似 · 拖出去 |

> 注意 **AI 评分和主色筛选不要一起收掉**。从一堆截图里挑好图、按颜色找配图，正是纯管理用户的刚需，它们不是摄影专属功能。

配置上就两个字段（`settings.ts` 加）：

```ts
useCase: 'manage' | 'pro'        // 首启二选一，默认 'manage'
grownFeatures: string[]          // 用过即加入，之后常驻
```

### 7.5 施工补充

先做 §5 的 1–2（选片交付工作区），这三件事可以并行、互不依赖：

| # | 做什么 | 工时 | 依赖 |
| --- | --- | --- | --- |
| A | 首启二选一 + 侧栏「更多」分组 | 半天 | §5 第 4 步（侧栏三段化） |
| B | **Ctrl+V 粘贴入库** | 1 天 | 无，最值得先做 |
| C | 选片交付的文案去「客户」化 | 1 小时 | §5 第 1 步 |

**B 的优先级高于 A**。理由：分岔口解决的是"看完觉得复杂"，粘贴入库解决的是"根本用不起来"——后者更硬。

### 7.6 判断标准

重排完之后，用两个问题验，**分别问两类用户**：

> **商业摄影用户：你脑子里有几个"入口"？**
> 现在大概是七八个，理想是三个：导进来 → 整一整 → 交出去。

> **纯图片管理用户：从截图到用上，几步？**
> 现在要 4 步（保存文件 → 找文件夹 → 导入 → 再翻出来）。理想是 2 步：**Ctrl+V 存进来、Alt 拖出去**。

目标不是让界面变简单，是**让用户脑子里的模型变简单**——而且要分别变简单，不是折中成一个谁都不顺的版本。

## 8. 明确不做的

| 别做 | 原因 |
| --- | --- |
| 删掉低频功能 | 方向是**收纳**不是砍。删了主人两周后自己会想不起来，然后又加回来 |
| 做「简单模式 / 专业模式」开关 | 切了回不去、用户会怕点，而且用户会成长。改成"随使用长出来" |
| 给两类用户各做一套界面 | 底盘共用，只在入口处分岔。两套界面等于两倍维护量，还会慢慢长歪 |
| 把 AI 评分、主色筛选当成摄影功能收掉 | 从一堆截图里挑好图、按颜色找配图，正是纯管理用户的刚需 |
| 把「选片交付」做成独立窗口 | 它应该是主界面里的一个视图，跟人像工作台同级，不要另开 BrowserWindow |
| 为了"看起来简洁"把入口藏进二级菜单 | 藏起来的东西等于不存在。要么露在外面，要么按需自动长出来 |
| 重排时顺手改业务逻辑 | 只搬位置、只改 label。逻辑改动出问题时，会分不清是搬坏的还是改坏的 |
