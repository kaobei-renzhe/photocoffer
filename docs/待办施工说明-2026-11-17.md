## ⚠️ 三个必须先知道的坑

### 坑 1 · 删「编辑」菜单会让 macOS 的 ⌘C/⌘V 失效

`src/main/platform.ts:35` 有明确注释：

> 绝不能 `setApplicationMenu(null)`，否则 Ctrl+Z/C/V 会失去加速键来源。

而且 `ROLE_BY_ID` 里 `edit.cut/copy/paste/undo/redo/selectAll` 走的是 **Electron 原生 role**。macOS 上这些 role 是系统级复制粘贴的唯一来源——**菜单项删了，⌘C 就真的不能用了**。

**正确做法**：macOS 保留一个**不可见**的编辑菜单撑住 role：

```ts
...(isMac
  ? [{
      label: '编辑',
      visible: false,          // 不可见，但 role 仍然注册加速键
      submenu: [
        { role: 'undo' }, { role: 'redo' }, { type: 'separator' },
        { role: 'cut' }, { role: 'copy' }, { role: 'paste' }, { role: 'selectAll' }
      ]
    }]
  : [])
```

Windows 上编辑菜单本来就是 `click` 转发（`platform.ts:46-49` 特意不注册 role，避免抢渲染层的撤销/全选），删掉不影响快捷键。

### 坑 2 · 改名会换 userData 目录，老用户数据会"消失"

`src/main/index.ts:167-171`：

```ts
const LEGACY_APP_DIRS = ['砚白', '片匣', '月相', 'lunaris', '月巢', 'moonnest', 'image-nest']
```

改 `package.json` 的 `name` 后，`app.getPath('userData')` 会从 `%APPDATA%\lunaris` 变成 `%APPDATA%\photocoffer`。代码里已有"回退读旧目录"的逻辑，**但前提是新名字不能出现在列表里、旧名字必须在**。

**动之前先确认 `LEGACY_APP_DIRS` 里含 `lunaris`** —— 现在已经有，别删。

### 坑 3 · 删自动播放要连带清理 `slideIdle`，否则沉浸失效

`src/renderer/src/lib/chromeVisibility.ts` 的签名里有个 `slideIdle`：

```ts
if (input.immersive) return input.peekBand
return !input.slideIdle
```

它是"幻灯片播放时静止 3 秒才隐藏工具"的机制。删掉自动播放后 `slideIdle` 恒为 `false`，这段逻辑变成死代码。**清理时一并删掉参数**，并同步改 `chromeVisibility.test.ts`（否则测试会报"多余参数"或行为不符）。

### 为什么不改 appId（重要决策）

`appId` 现在是 `com.silvermoon.cunzhao`，和新名 `photocoffer` 不一致。**建议保留不动。**

| 理由 | 说明 |
| --- | --- |
| appId 是**安装标识**，不是品牌名 | Windows 的卸载注册表项、macOS 的 bundle identifier 都靠它。改了等于告诉系统"这是另一个应用"，**已安装的 0.4.x 无法被覆盖升级**，用户机器上会出现两个应用 |
| 用户看不到它 | 界面显示的是 `productName`（存照），appId 只出现在安装目录、注册表和签名里 |
| 里面的 `cunzhao` 本身不是错误 | 存照的拼音，语义没错，只是和新英文名不同源 |

如果坚持要统一成 `com.silvermoon.photocoffer`，必须配套：旧版检测 → 引导用户卸载旧版 → 数据目录迁移 → 更新通道双写过渡。**成本远大于收益，本次不做。**
