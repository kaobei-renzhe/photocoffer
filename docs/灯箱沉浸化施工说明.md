## 第 1 批 · 黑底 + 去胶囊容器

### 1.1 `styles.css` 新增固定深色类

**位置**：`:root[data-skin='contrast']` 块结束之后、`:root[data-skin] .btn` 之前（约第 341 行）

```css
/* 灯箱固定深色舞台：不随主界面主题变，看片时排除界面色的视觉干扰 */
.lightbox-fixed-dark {
  --lightbox: #0B0B0B;
  --lb-chrome: rgba(22,22,22,.86);
  --lb-rule: rgba(255,255,255,.10);
  --lb-text: #F2F2F2;
  --lb-faint: #A6A6A6;
  --lb-hover: rgba(255,255,255,.10);
  --lb-matte: rgba(255,255,255,.10);
}
```

**为什么这样写**：
- 只作用在灯箱根节点上，**不动 `:root` 和四个主题块**，主界面完全不受影响
- `--lb-matte` 从 `#FFFFFF` 降到 `rgba(255,255,255,.10)` —— 这是关键：不改的话照片白衬在纯黑背景上会变成**刺眼的白框**
- 保留 `.10` 而不是去掉：夜景/低调人像的暗部会融进纯黑背景，这道极淡勾边是**功能性**的，用来标出照片边界

## 第 3 批 · 无障碍与自动隐藏状态机

### 3.1 删掉 `inert` 与 `aria-hidden`（4 处）

**这是必须改的** —— `inert` 会把元素从 Tab 序列和读屏树里彻底移除，等于「自动隐藏」时**对键盘和读屏用户删掉了全部功能**。

| 行号 | 现状 | 改法 |
| --- | --- | --- |
| `693` | `inert={!chromeVisible}` | 删除 |
| `694` | `aria-hidden={!chromeVisible}` | 删除 |
| `906` | `inert={!chromeVisible}` | 删除 |
| `907` | `aria-hidden={!chromeVisible}` | 删除 |
| `928` | `inert={!chromeVisible}` | 删除 |
| `929` | `aria-hidden={!chromeVisible}` | 删除 |

**替代做法**：控件常驻 DOM，静止时只降 `opacity`；用 `pointer-events: none` 防止误点。现有的 `chromeCls` 已经在切 opacity，所以视觉上没差别，但键盘和读屏能摸到。

视觉不可见时的写法（如果担心透明元素仍被点击）：

```tsx
className={`... ${chromeVisible ? 'pointer-events-auto' : 'pointer-events-none'}`}
```

### 3.2 `chromeVisibility.ts` 扩展状态机

现在只有三个输入：

```ts
export function isChromeVisible(input: {
  immersive: boolean
  peekBand: boolean
  slideIdle: boolean
}): boolean {
  if (input.immersive) return input.peekBand
  return !input.slideIdle
}
```

改成：

```ts
export function isChromeVisible(input: {
  immersive: boolean
  peekBand: boolean
  slideIdle: boolean
  /** Tab 聚焦到任一控件 */
  focusWithin?: boolean
  /** 框选拖拽进行中 */
  drawing?: boolean
  /** 档案面板打开 */
  inspectorOpen?: boolean
  /** 二级面板展开 / 指针按下 / 播放中 */
  interacting?: boolean
}): boolean {
  // 用户正在交互时，一律常显，绝不中途消失
  if (input.focusWithin || input.drawing || input.inspectorOpen || input.interacting) return true
  if (input.immersive) return input.peekBand
  return !input.slideIdle
}
```

调用处（`Lightbox.tsx:130`）补上新参数：

```tsx
const chromeVisible = isChromeVisible({
  immersive,
  peekBand,
  slideIdle,
  focusWithin,      // 新增：用 stageRef.current?.contains(document.activeElement) 算
  drawing,
  inspectorOpen,
  interacting: moreOpen || slideshow
})
```

### 3.3 箭头去掉 `tabIndex={-1}`（`Lightbox.tsx:846` 与 `860`，两处）

隐藏时如果设 `tabIndex={-1}`，键盘用户永远摸不到翻页按钮。改成跟随 `chromeVisible`：

```tsx
// 改前（两处都是）
tabIndex={chromeVisible ? 0 : -1}

// 改后：直接删掉这一行，让 button 用默认的可聚焦行为
```

（配合 3.1，控件本身已经常驻 DOM 了。）

### 3.4 静止态的对比度下限

控件静止 `opacity: .38` 在纯黑底上，`#F2F2F2 × .38` 约等于 `#5C5C5C`，对 `#0B0B0B` 的对比度约 **4.4:1** —— 刚好够用。如果实测觉得太淡，可以提到 `.45`（约 5.6:1），**别低于 .38**。

## 明确不做

| 别做 | 原因 |
| --- | --- |
| 不改 `:root` 和四个主题块里的 `--lb-*` | 那会影响主界面；固定深色只作用在灯箱根节点 |

| 不把 `--lb-matte` 完全去掉 | 夜景 / 低调人像会融进背景，必须有那道极淡勾边 |
| 不改箭头 `bg-white/8` + `text-white/80` | 深色灯箱下这本来就是正确写法（浅色版才需要改） |
| 不改提示条 `bg-black/70` | 同上 |
| 不移除 `inert` 后忘记加 `pointer-events-none` | 会导致透明控件被误点 |
| 不删「6 / 200」计数 | 静止态唯一的方位锚点 |
| 不给右上角 Windows 三键做设计 | 系统层，不可改 |
| 不做「首次使用提示」 | 可选增强，先别引入持久化状态 |
| 不改框选草稿的近白虚线 | `#F2F5F8` + 黑外描边是刻意双描边，任意明暗照片上都可见 |
