# 界面文案优化方案

> 扫描范围：`src/renderer/src` 下 51 个文件，过滤掉代码注释后提取到
> **界面文本 324 条 / title 提示 97 条 / placeholder 19 条 / 字符串文案 778 条**。
>
> 结论：文案总量不算多，问题集中在三类——**术语泄漏、零信息前缀、长句塞界面**。

---

## 1. 诊断

### 问题一：实现术语漏到界面上（最该改）

开发者脑子里的词，用户脑子里没有对应概念。**实测频次**（`src/renderer/src` 下，排除注释）：

| 级别 | 术语 | 界面 | title | 典型 |
| --- | --- | --- | --- | --- |
| **必改** | `mtime` | 0 | 1 | 「对比侧车 mtime，导入外部软件的修改」 |
| **必改** | `侧车` | 6 | 2 | 「启用 XMP 侧车」「XMP 侧车」 |
| **必改** | `token` | 5 | 4 | 「最大输出 tokens」「每次请求都会消耗 token」 |
| 看情况 | `语义` | 27 | 2 | 「正在后台建立语义索引」「语义模型下载完成」 |
| 看情况 | `索引` | 38 | 4 | 「语义索引失败」「上次的索引目录里没有 library.db」 |

> **为什么分两级**：`mtime` / `侧车` / `token` 是**用户完全没有对应概念**的词，看到只能跳过。而 `语义` / `索引` 是行业通用说法，数量虽多（合计 71 处），改了不一定更好——**别为了换词把 70 多处都动一遍**，那是另一个风险。真要动，只动用户会盯着看的那几处（进度条、错误提示）。

> 统计口径：同一行里如果是 `item.mtime`、`<option value="mtime">`、`cost.tokens` 这类变量，**不计入**——它们不显示给用户。

**`mtime` 是最严重的**——这是 Node.js 文件系统 API 的属性名，直接写进了界面提示。

**`侧车`（XMP sidecar）次之**——这词在中文摄影圈都不常这么说，用户看到会想"什么车？"。

### 问题二：「全部 xxx」是零信息前缀

工具栏上有四个：`全部星级` `全部 AI 评分` `全部构图` `全部旗标`。

用户读到「全部」会理解成"所有照片"，但它实际的意思是**"这个筛选没生效"**。

### 问题三：62 条说明文字超过 16 字

典型样本：

> 选择一个文件夹，月相会扫描并识别其中的照片（JPG、PNG、RAW、HEIC、TIFF 等）。导入在后台进行，期间可以继续浏览和整理其它照片。

一句话里塞了：操作 + 支持的格式列表 + 后台行为 + 可以做别的。三条信息挤在一个段落里。

## 2. 术语对照表（按优先级）

| 现在 | 改成 | 为什么 |
| --- | --- | --- |
| 最大输出 **tokens** | 单次回复长度 | 用户不知道 token 是什么 |
| 这次 AI 评分会消耗较多 **token** | 这次评分花的时间会久一些 | **说结果，不说单位** |
| 启用 XMP **侧车** | 把评分和标签写进照片的 `.xmp` 文件 | 侧车是行话，`.xmp` 是可见实体 |
| 对比侧车 **mtime**，导入外部软件的修改 | 检查照片信息有没有被别的软件改过 | mtime 是代码词，必须消失 |
| 闲时自动建立**语义索引** | 空闲时自动识图 | 索引是实现细节 |
| **语义**搜索需要先下载模型 | 描述搜图需要先下载识图模型 | 「语义」太抽象 |
| 正在后台建立**语义索引** | 正在后台识别图片，完成后就能按描述搜 | 说得清在干什么 |
| **维度** | 分类 | 维度是设计术语 |
| 上次的**索引目录**里没有 library.db | 找不到这个图库的数据文件 | 别让用户看见文件名 |
| AI 处理范围 | AI 作用的照片 | 范围偏抽象 |

### 关于 `token` 的特殊处理

用户真正关心的是**"点一下要花多少钱 / 等多久"**，不是消耗了多少个单位。

三个层次的做法，从简到繁：

1. **最简**：删掉 token 这个词，只说「会多花一点时间」
2. **中等**：显示张数「这次会评估 12 张，大约 30 秒」
3. **最好**：如果配置了单价，直接算钱「预计 ¥0.08」

第 3 种最友好，但要维护各服务商的价格表。**建议先做第 2 种。**

## 3. 「全部 xxx」怎么改

**现在**：`全部星级▾` `全部 AI 评分▾` `全部构图▾` `全部旗标▾`

**改成**：

```
未选时： 星级▾   AI 评分▾   构图▾   旗标▾
已选时： 星级 · 3★以上 ▾      ← 直接显示当前条件
```

关键在于**选中后标签要变成条件本身**。用户一眼看到"现在筛的是 3 星以上"，不用点开确认。

这个改动只涉及 4 个按钮的 label 逻辑，半小时的事。

## 4. 长文案改写示例

### 示例一：导入说明

**现在（58 字）**
> 选择一个文件夹，月相会扫描并识别其中的照片（JPG、PNG、RAW、HEIC、TIFF 等）。导入在后台进行，期间可以继续浏览和整理其它照片。

**改成（22 字）**
> 选一个文件夹，月相会扫描并导入里面的照片。

支持格式移进 `title`：`支持 JPG / PNG / RAW / HEIC / TIFF 等`。
"后台导入"这件事不用说明——用户看到进度条自然知道。

### 示例二：自动分类说明

**现在（约 70 字）**
> 每张图只会归到一个最相似的类目；只对已建立语义索引的图片生效，重复运行会按新阈值重新归类，不会重复打标签。

**改成（两条短句）**
> 每张照片归到一个最像的分类。
> 可重复运行，不会重复打标签。

"只对已建立语义索引的图片生效"这条**不需要说**——没索引的用户点了没反应，界面直接提示"需要先识图"就行，属于运行时反馈，不该占说明位置。

### 示例三：AI 建议弹窗

**现在（42 字）**
> 点下面的「生成建议」才会把这张图发给模型，每次请求都会消耗 token；不点就不会产生费用。

**改成（18 字）**
> 点了才会把这张图发给模型，不点不产生费用。

## 5. 三条原则

### ① 说结果，不说机制

| 机制 | 结果 |
| --- | --- |
| 消耗 1200 token | 大约 30 秒，花几分钱 |
| 对比 mtime | 检查有没有被别的软件改过 |
| 建立语义索引 | 自动识图 |
| 索引数据库 | 图库的数据文件 |

用户不关心你是怎么实现的，只关心**会发生什么**。

### ② 一句话只装一件事

超过 25 字就该拆。拆不开说明这地方塞了两件事，需要重新组织（一条放界面，一条放 hover）。

### ③ 解释放 hover，不放界面

`title` 属性就是干这个用的。项目里已经有 97 条 title，这个习惯是对的——**继续用，别往正文里堆**。

---

## 6. 值得保留的（不用改）

扫描里发现这些写得挺好，说明主人本来就有文案意识：

- **placeholder 全部是"例如：xxx"格式** —— `例如：小林 · 老门东街拍`、`比如 Zf、24-70、三脚架…`
  比"请输入标题"好一百倍，用户直接知道该填什么样式。
- **销毁类操作说清了范围** —— 「只删 1440px 那档，日常浏览不受影响」「只动索引，不动磁盘，可撤销」
- **AI 功能反复强调"不点不花钱"** —— 这是建立信任的关键，保留。

---

## 7. 施工建议

按「改动量 ÷ 收益」排序：

| 批次 | 改什么 | 工作量 | 收益 |
| --- | --- | --- | --- |
| **第一批** | 干掉 `mtime`、`侧车`、`token` 三处 | 30 分钟 | 最高——这三个词用户根本看不懂 |
| **第二批** | 四个「全部 xxx」改成条件显示 | 30 分钟 | 高——每天都要看几十次 |
| **第三批** | 62 条长文案挑前 15 条改写 | 2 小时 | 中——主要在弹窗里，不是天天看 |
| 第四批 | 建一份术语表，新文案照着写 | 持续 | 长期——防止再漏进来 |

第一批建议今天就改，因为**改三个词的成本几乎为零，但收益立刻可见**。

## 8. 自检方法

改完之后，用这个办法验：

> **把界面截图发给一个不玩电脑的家人，问他"这个按钮点了会怎样"。**
> 他答得上来 = 文案合格；他要反问"这个词啥意思" = 还得改。

另一个更快的：**全文搜索这几个词，界面上出现即为不合格**：

```
mtime   token   侧车   sidecar   dpr   IPC   库索引   facet
```

代码里随便用，界面上一个都不能有。

## 明确不做的

| 别做 | 原因 |
| --- | --- |
| 把「语义」「索引」也全改一遍（合计 71 处） | 它们是行业通用说法，改多了是另一种风险。只动用户盯着看的那几处（进度条、错误提示） |
| 顺手重构文案逻辑 | 只改字符串和 label 表达式，不动条件分支 |
| 删掉「不点不花钱」这类承诺 | 改 `token` 时最容易被当成废话删掉，而它正是建立信任的关键 |
| 用高级词汇替换口语 | 「存档」不如「保存」，「获取」不如「拿到」。越日常越好 |
| 一次改完所有文案再验收 | 按批次改，一批看一眼。文案错误只有看了才发现 |
